## Objective

Establish that the vertical mobile Timeline is a deliberate second layout
rather than the desktop rail rewrapped, and put that fact under a test so the
next refactor cannot flatten it back.

## Business reason

Most people who open a couple's link open it in a message app, on a phone, once.
That single view is the whole impression the venue paid for. A horizontal rail
squeezed onto a 390px screen is the failure mode, and it is the failure mode
that arrives silently when someone tidies the CSS.

## Intended outcome

The vertical layout is recorded as shipped work with evidence, and CI holds its
identity: rail axis, label behaviour, Today marker orientation, and the fact
that it is driven by container width rather than viewport width.

## Implementation approach

Read the shipped CSS against the criteria, record what passes, and build only
what is missing. What was missing was not layout. It was that nothing in the
registered test suite said the layout exists, and the one file that did say so
had never been wired into CI and had gone red without anyone noticing.

## Acceptance criteria

1. The rail flips its coordinate system below the breakpoint rather than
   rewrapping: horizontal geometry becomes vertical geometry, milestones
   position by block offset instead of inline offset, and the vertical
   completed rail replaces the horizontal one.
2. The Today marker rotates a quarter turn with it, and its label moves out of
   the rail's path.
3. Collision avoidance is replaced by showing every label. On a wide rail
   crowded labels are hidden; on the vertical rail there is room for all of
   them and none is hidden.
4. The layout is chosen by **container** width, not viewport width, so the same
   artifact is correct inside the owner's panel and inside the phone preview.
   No viewport media query may decide layout.
5. The existing keyboard contract is unchanged: Left and Right between
   milestones, Home and End to jump, Enter or Space to select, Escape to close,
   with a roving tab index, `aria-expanded`, `aria-controls` and a polite live
   region.
6. `prefers-reduced-motion: reduce` disables the rail, label, point, metric and
   Today marker animation.
7. Zero critical and zero serious axe violations at 390, 768, 1280 and 1440,
   and no horizontal document overflow at any of them.
8. Every assertion above runs in CI. A layout contract in an unregistered file
   is the same defect class as R-028.

## Objective

Run the real checks across every Venue Edition commercial surface, fix what is
in scope, and report every remaining defect with its measurement rather than an
assurance.

## Business reason

This is the only task on E12 that is `criticalPath: true`. Nine commercial
surfaces were built by five concurrent work streams in one day against a copy
system that no gate on this branch currently enforces. Something in that will be
wrong, and the whole value of this task is finding it before a venue does.

## Intended outcome

Every commercial surface has been loaded in a real browser at four breakpoints
and measured. The analytics position is proved by request logs rather than
asserted from source. Every page states what a venue does next. Every remaining
defect is named with a file, a line and a number.

## Deliverables

- [x] The analytics position verified at the network layer on a production-mode
      server, not read from code.
- [x] A conversion pass over every commercial page, with the two pages that had
      no next step fixed.
- [x] An accessibility, responsive and reduced-motion sweep at 375, 768, 1280
      and 1600, using axe with wcag2a/2aa/21a/21aa.
- [x] The `prohibited-claims.v1.json` rules applied to all thirteen E12
      surfaces, producing the pin values WP-06's `[venue-copy]` stage will need.
- [x] The final banned-term and claim sweep across every file the package
      touched.
- [x] `evidence/E12.14-commercial-qa-sweep.md` with every number.

## Scope

Nine routes: `/venues`, `/venues/demo`, `/venues/privacy`, `/venues/questions`,
`/venues/couple-preview`, `/venues/what-you-see`, `/v/<token>` in both its
states, and `/hq/venue-proposal`. Plus every source file the package created or
changed.

## Non-goals

- **Redoing E12.04.** `/venues` is Done and live. Its defects are reported, not
  edited.
- **Deciding R-032, the site-wide consent position.** D-032 R8 ratified the
  carve-out for Venue Edition surfaces and that is what is verified. The
  position on every other public page is a founder call and is untouched.
- **Changing a design-system token.** The dominant accessibility finding is a
  DS colour pair used site-wide. Recommendation only.
- **Satisfying `design:quality`.** I-014. This task hands over a review.
- **Editing `prohibited-claims.v1.json`.** It is WP-06's in-flight contract.
  This task supplies the measured pin values; WP-06 lands them.
- **Lighthouse or field performance numbers.** No harness exists in this
  repository and inventing one under a deadline produces a number nobody can
  reproduce. What is measured is stated; what is not is named as not measured.

## Implementation approach

Measure first, fix only what is unambiguously in scope and cannot make the
experience gate worse, report everything else. Every fix is re-verified by
re-running the same measurement against a fresh production build, because the
first re-run of the accessibility harness silently ran against a stale server
and would have reported a fix that had not landed.

## Acceptance criteria

1. The third-party analytics position on every Venue Edition commercial surface
   is proved by observed network requests on a production-mode server, with a
   control route that does fire the tag, and D-032 R8 is satisfied.
2. `/v/` is disallowed in the served `robots.txt` and absent from the served
   `sitemap.xml`, verified against a running server.
3. Every commercial page states what a venue does next and provides the means to
   do it. A page whose closing copy invites an action it does not offer is a
   defect and is fixed.
4. Every route is loaded at 375, 768, 1280 and 1600 and produces zero horizontal
   document overflow.
5. Every route has exactly one h1, no skipped heading level, one main landmark,
   and no image without an alt attribute.
6. Every serious or critical axe violation is either fixed or reported with its
   rule id, its measured contrast ratio or node count, its owner and the reason
   it was not fixed here.
7. Keyboard focus order is walked on every route and no focus stop is
   off-screen.
8. Under prefers-reduced-motion, no element on any route is still running a
   non-trivial animation or transition.
9. `prohibited-claims.v1.json` is applied to all thirteen E12 surfaces, the pin
   on `/venues` is confirmed to still hold, and every hit is classified as a real
   defect or a false positive with its cause.
10. The final banned-term sweep covers programme terms, permanence, VAT-exclusive
    statements, urgency and countdowns, seat counts, and legal, solicitor,
    accountant and GDPR claims, across every file the package touched, and
    reports every hit with file and line, fixed or not.
11. `typecheck`, `test`, `build` and `ds:check` pass; any gate that fails is
    reported as failing with its exact output and its owner.
12. The count of `experience:validate --product=studio` failures is reported
    before and after, and is not increased by this task.

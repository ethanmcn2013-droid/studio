# E04.02 — Define venue member roles and permissions for owner, manager and viewer.

**Task ID:** E04.02
**Epic:** E04 — Venue Edition product architecture and workspace lifecycle
**Status:** Founder Review

---

## Objective

Reconcile the documented 13-row capability matrix against the six capabilities actually shipped, and state which are enforced.

## Business reason

A venue's staff will hold these roles from the first onboarding. A capability that is documented but unenforced is a privacy claim the product cannot keep, which is R-007 in its most direct form.

## Intended outcome

One table shows doc position, shipped position and gap per capability, so the enforcement backlog is visible instead of assumed.

## Deliverables

- [ ] studio/docs/architecture/ADR-008-venue-edition-lifecycle.md section 2, the reconciled matrix
- [ ] The six membership invariants restated with an enforced or not-enforced verdict each

## Scope

Reconciliation and gap statement across the doc and the shipped code.

## Non-goals

Building sponsor_members. Implementing enforcement. Adding roles. Enforcement is E07 work and needs the member table first.

## Dependencies

| Dependency | State | Waived? |
|---|---|---|
| E04.01 | in this package | no |

## Inputs

studio/docs/venue-portal/ROLES_AND_PERMISSIONS.md, studio/src/lib/account/roles.ts, studio/src/lib/entitlements-db/sponsorship-policy.ts.

## Implementation approach

Audit both sources, produce one table, and name the capabilities with no enforcement path at all rather than describing the matrix as if it governs.

## Acceptance criteria

1. Every capability in the documented matrix appears with its shipped counterpart or an explicit gap.
2. Capabilities with no runtime enforcement are named as unenforced.
3. The six invariants each carry an enforced or not-enforced verdict.
4. No role or capability is invented that neither source contains.

## Validation plan

Reviewer diffs the section against ROLES_AND_PERMISSIONS.md and roles.ts.

## Evidence required

- studio/docs/architecture/ADR-008-venue-edition-lifecycle.md

## Risks

R-007. The portal's privacy story rests on the viewer boundary, and the shipped capability set does not currently distinguish viewing a code from downloading one.

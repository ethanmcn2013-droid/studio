## Objective

State the three-way data boundary in one place, with the enforcing code and the proving test for each class.

## Business reason

The privacy claim is the product. R-007 is the risk that the claim outruns the implementation, and a boundary documented in two separate files is a boundary nobody has checked end to end.

## Intended outcome

Private, public-artifact and venue-aggregate are one table with enforcement and proof per class, and the gap between the three-way statement and what is enforced is named.

## Deliverables

- [ ] studio/docs/architecture/ADR-008-venue-edition-lifecycle.md section 8, the three-class boundary

## Scope

Consolidating the venue-aggregate boundary and the public-artifact boundary into one statement, with enforcement and tests cited.

## Non-goals

Changing any allowlist. Changing suppression thresholds, which are ratified in D-011 point 3.

## Implementation approach

Audit. Consolidate. Name the gap rather than closing it silently.

## Acceptance criteria

1. Three data classes are stated in one place with what belongs in each.
2. Each class cites the code that enforces it and the test that proves it.
3. The fail-closed behaviour on unknown sponsor fields is stated.
4. Suppression thresholds of 3 and 5 appear as ratified in D-011 point 3.
5. Any part of the three-way boundary with no enforcement is named as unenforced.

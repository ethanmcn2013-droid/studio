## Objective

Produce one page that states the current approved position on the offer, the
product model, the geography, both films and every superseded assumption, so that
no later session has to reconstruct it from chat history or from twenty-four
decision entries.

## Business reason

Twenty-four decisions across two days settled the entire commercial and product
position. They live in an append-only log that reads chronologically, not by
subject. Every subsequent session, subagent and venue-facing asset needs the
current position in one read. A session that gets the price, the term or the
entitlement wrong writes it into a contract sent to 25 businesses.

## Intended outcome

A reader who has never seen this project can state the offer, the product model,
the geography, both films and what has been retired, correctly, in two minutes.

## Deliverables

- [x] `BRIEF.md` at the control root, one page, covering all five required subjects
- [x] An explicit "What this replaces" table naming each superseded position, the decision that replaced it, and whether the repository has caught up
- [x] Brand-voice compliance, mechanically checked

## Scope

The current approved position as at 2026-08-03, drawn from D-001 to D-024,
PROJECT.md, CR-001 and the RAID entries those decisions opened.

## Non-goals

- Not a replacement for `DECISIONS.md`. The decision log stays canonical and outranks the brief.
- Not a rationale document. Why a decision was made lives in its decision entry.
- Not a status report. Progress, gates and counts live in `STATUS.md`.
- Not the backlog. No task list.
- **Not ten pages.** The named failure mode for this task is elaboration.

D-001 to D-024 are all recorded and the baseline is approved, so the inputs exist.

## Inputs

- `DECISIONS.md` D-001 to D-024 — controlling
- `PROJECT.md` §5 to §10 — controlling, subordinate to DECISIONS.md
- `evidence/change-requests/CR-001.md` — approved as D-023
- `RAID.md` R-011, R-015, R-016, R-018, R-021, R-022, I-002 — the exposures the brief must not hide
- `BASELINE_REVIEW.md` §10 — the eight inconsistencies detected at import
- `studio/BRAND.md` §3 — voice

## Implementation approach

Write the five required subjects as five short sections, then the superseded
table last and longest, because that is the section that prevents the failure this
task exists to prevent. Distinguish "the decision superseded it" from "the file
still says the old thing" in a status column: a brief that flattens those two
states would license a session to believe the repository is already correct.
Verify every claim adversarially against primary sources before review.

## Acceptance criteria

1. `BRIEF.md` exists at the control root and covers all five subjects named in the task title: current offer, product model, geography, both films, superseded assumptions.
2. Every factual claim in it is traceable to D-001 to D-024, PROJECT.md or CR-001, and an independent adversarial check found no wrong claim.
3. Every superseded position is named explicitly with the decision that replaced it. Nothing is superseded silently.
4. The brief distinguishes decisions that are recorded from decisions the repository has not yet implemented, and names the live defects.
5. It is one page. Not a document set, not a second decision log.
6. It passes the mechanical brand-voice check with zero findings, and contains no em dash or exclamation mark.
7. It states plainly what is still open, including the accepted exposures, rather than reading as if everything is settled.

## Validation plan

- `node ~/.claude/skills/brand-voice/voice-check.mjs BRIEF.md` — expect zero findings
- An independent adversarial fact-check subagent verifies every number, every decision ID citation, every risk ID citation, and every file path claimed to still carry an outdated position, against primary sources
- The same check reports omissions: any superseded assumption in D-001 to D-024 or BASELINE_REVIEW.md §10 that the brief fails to list

## Evidence required

- `BRIEF.md` itself
- The voice-check output
- The adversarial fact-check findings, including anything it corrected

## Risks

Amplifies nothing. Mitigates the standing risk that a session acts on a
superseded assumption. If the brief is wrong it is worse than no brief, which is
why the fact-check is a criterion rather than a nicety.

## Decisions required

None. Every input is already ratified.

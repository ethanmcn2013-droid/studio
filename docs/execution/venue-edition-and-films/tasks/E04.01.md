# E04.01 — Define the data entities for venue, agreement, term, founding status, member, invitation, couple workspace and public artifact.

## Objective

Publish one authoritative inventory of the eight Venue Edition entities, saying for each exactly where it lives today and what does not exist yet.

## Business reason

Five downstream epics build on these entities. Every hour spent guessing which table holds a venue's term, or discovering mid-build that no agreement entity exists, is an hour taken from the 29 days before release.

## Intended outcome

Any session can answer 'where does this live' from one file instead of by grep, and the three entities that are absent are absent on the record rather than by surprise.

## Deliverables

- [ ] studio/docs/architecture/ADR-008-venue-edition-lifecycle.md section 1, the eight-entity inventory with a shipped/partial/absent verdict and a file path per entity
- [ ] The three named absences recorded as findings: no agreement entity, no founding-number field, sponsor_members designed but not built

## Scope

Documenting what exists and what does not, against the ratified decisions. Recording gaps as findings.

## Non-goals

Building the missing entities. Creating sponsor_members. Assigning founding numbers. Each is its own task in E02 or E07, and none belongs in a definition task.

## Dependencies

| Dependency | State | Waived? |
|---|---|---|
| — | n/a | no |

## Inputs

studio/src/lib/entitlements-db/schema.ts, app/src/server/db/schema.ts, studio/docs/venue-portal/PRODUCT_CONTRACT.md, ADR-007, D-009 point 6, D-020.

## Implementation approach

Audit first per D-015 Q2. Read the shipped schemas in both repos, map each of the eight named entities onto real columns, and record an honest verdict. Where a ratified decision names something the schema cannot express, record the conflict rather than reconciling it.

## Acceptance criteria

1. All eight named entities appear in the inventory with a repo, table and file path, or an explicit 'absent'.
2. Every entity carries a shipped, partial or absent verdict, and no verdict claims more than the code does.
3. The absence of an agreement entity, a founding-number field and sponsor_members is stated explicitly.
4. Every claim in the section is traceable to a file path a reviewer can open.

## Validation plan

Reviewer opens three cited paths at random and confirms the section describes what is there.

## Evidence required

- studio/docs/architecture/ADR-008-venue-edition-lifecycle.md

## Risks

A definition that flatters the implementation is worse than none, because downstream sessions will trust it. R-007 applies: claims must not outrun the code.

## Decisions required

None. Building the absent entities is separate scope.

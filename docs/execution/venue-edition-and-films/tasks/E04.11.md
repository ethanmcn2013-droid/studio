## Objective

Collect the lifecycle edge cases scattered across five documents and the RAID register into one enumerated list with expected behaviour.

## Business reason

D-001 point 17: portal and reporting edge cases are not optional post-sale work. An edge case found by a founding venue costs the reference; the same case found now costs an hour.

## Intended outcome

One enumerated list, each with expected behaviour and a state on whether the machine or the code covers it.

## Deliverables

- [ ] studio/docs/architecture/ADR-008-venue-edition-lifecycle.md section 11, the edge-case register
- [ ] studio/src/lib/venue-lifecycle.test.ts coverage for the cases the state machine can express

## Scope

Collection, expected behaviour, and a covered or uncovered verdict per case.

## Non-goals

Implementing the uncovered cases.

## Dependencies

| Dependency | State | Waived? |
|---|---|---|
| E04.07 | in this package | no |

## Inputs

studio/docs/LICENSING_ACCESS_DESIGN.md, studio/docs/venue-portal/IMPLEMENTATION_AND_TEST_PLAN.md, PRIVACY_AND_RETENTION.md, ROLES_AND_PERMISSIONS.md, RAID.md.

## Implementation approach

Harvest rather than invent. Where the state machine already answers a case, say so and cite the test; where it does not, say that instead.

## Acceptance criteria

1. Every edge case carries expected behaviour, not just a description.
2. Each case is marked covered by a test, covered by a rule, or uncovered.
3. The cases the state machine covers cite their test.
4. No case is described as handled when it is not.

## Validation plan

## Evidence required

- studio/src/lib/venue-lifecycle.test.ts

## Risks

An uncovered case list is only useful if it is worked. It feeds E05 to E09 planning.

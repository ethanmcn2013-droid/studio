## Objective

Keep one authoritative count of founding places taken, assign each number on
cleared payment, and publish venue names only where permission is recorded.

## Business reason

D-009 point 6 makes the number the one promise with no correction path. Two
venues told they hold 01/25 cannot both be right and neither can be made right
afterwards. D-027 point 2 exists for exactly this reason.

## Intended outcome

The database is the counter. Every assigned number is unique, in range, and
assigned after the payment cleared. Every published name has a permission behind
it.

## Deliverables

- [ ] The counter, derived from the database rather than maintained by hand.
- [ ] The assignment record per venue.
- [ ] The published-names list, each entry traced to a permission.
- [ ] The integrity run output after each assignment.

## Scope

`sponsors.founding_number`, `sponsors.founding_number_assigned_at`, the unique
partial index, `assignFoundingNumber`, `check-entitlements-integrity.mjs`, the
founding certificate, and any public surface that names a venue.

## Non-goals

- A manufactured countdown. Scarcity must be a static true statement, never a
  ticking number that can go stale.
- Publishing a name without permission (D-010 point 1, E10.14).

## Acceptance criteria

1. The count of founding places taken is computed from
   `sponsors.founding_number` and never maintained anywhere else. Any second
   copy is a derived display, labelled as such.
2. Every assigned number is unique, enforced by the unique partial index, and
   within 1 to 25.
3. No number is assigned before its venue's payment cleared. The integrity check
   for this is already written and passing.
4. Assignment is idempotent: re-running the assigner for a venue that holds a
   number returns the same number and writes nothing new.
5. `pnpm entitlements:integrity` exits 0 after every assignment, against
   production.
6. The founding certificate for a venue renders the same number the database
   holds, in the form `NN/25`.
7. Any public statement of places remaining is a static true statement at the
   time of writing, with a date, and is never presented as a live countdown.
8. A venue name is published only where the permission register carries a row
   for that exact use.

## Risks

- **Nothing detects a cleared payment automatically.** The operator todo
  `apply-venue-edition-terms-migration` records it: *"the field is ready; the
  trigger is not."* Assignment depends on a human noticing money landed.
- Two venues holding the same number is the failure with no correction path.
- A stale public count is a small lie that undermines a scarcity claim entirely.

## Decisions required

1. Is the number of places taken published at all before all 25 are gone? A
   static dated statement is safe; anything live is a maintenance commitment.

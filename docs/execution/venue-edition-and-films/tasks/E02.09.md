# E02.09 — Define the boundaries of founder access and product feedback so that the benefit does not become unlimited bespoke consultancy.

**Task ID:** E02.09 · **Epic:** E02 · **Status:** Founder Review
**Executor:** claude_code · **Approver:** Ethan McNamara · **Spec written:** 2026-08-03 (WP-10)

## Objective
Bound founder access and the feedback benefit before 25 venues hold them.

## Business reason
Founder capacity is the single constraint on this project (R-006). Twenty-five venues each believing they have an open line is the same failure as twenty-five bespoke builds.

## Intended outcome
Access is one call a year plus a named email route. Feedback is logged and shapes the roadmap, and nothing is built for one venue.

## Deliverables
- [x] Benefit 3 (founder access) and benefit 5 (requests) in the Benefits Charter, each with its boundary
- [x] The bespoke-development exclusion tied back to D-008 point 1

## Scope
The boundary language for access and feedback.

## Non-goals
A support SLA. A roadmap process. Escalation paths.

## Acceptance criteria
1. Access is quantified: one 30-minute call per venue per year, plus a named email route with a stated reply time.
2. It is stated not to be a retainer, an account manager or a standing arrangement, with the reason given.
3. Feedback is stated to be logged and prioritised ahead of non-founding requests, with "no" as an available answer.
4. Single-venue bespoke work is excluded in writing, with the test stated: a request that would help the next twenty-four gets built.

## Validation plan
Read-through against D-009 point 5, D-014 point 2 and D-008 point 1.

## Evidence required
The charter sections.

## Risks
The boundary holds only if it is repeated at signature. WP-04 carries it into the agreement.

## Decisions required
None.

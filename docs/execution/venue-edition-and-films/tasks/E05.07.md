## Objective

Establish which of the five named parts of task detail genuinely ship, close the
one that is broken for a two-person workspace, and refuse to build the two that
need a founder decision or belong to another work package.

## Business reason

A couple planning together is two people in one workspace. The task detail is
where the second person is talked to. If the mention list is empty until someone
has already spoken, the collaboration the venue is gifting does not start.

## Intended outcome

1. Comments, attachments and subtasks are each recorded as shipped or not, with
   a file and a line, so nobody rebuilds working code.
2. A couple can mention their spouse on day one.
3. It is written down that decisions do not exist as an object, and that
   attachments already have an upload path that E08.07 owns.

## Deliverables

- [x] Audit of all five named parts against written criteria.
- [x] Mention pool reads live workspace membership plus the task's assignees
      (`conversation-feed.tsx`, `task-detail.tsx`).
- [x] Source-scan contract test covering the mention pool as well as the assign
      menu.
- [x] Evidence document tracing every criterion to a file and line.
- [ ] Decisions as a first-class object — **not built.** Founder decision.
- [ ] Any change to the attachment upload or download path — **not built,
      deliberately.** Intersects E08.07.

## Scope

`src/components/app/detail-panel/**` and `src/components/app/task-detail/**`,
plus a read-only assessment of the server actions behind them.

## Non-goals

- Upload security hardening. The path exists with a mime blocklist, a per-file
  cap, a per-workspace quota, filename sanitisation, a claim-then-verify write,
  and a download route that re-checks the workspace and sends `nosniff` plus a
  sandbox CSP. Reviewing that is E08.07's job. Building a second upload path
  here would be an unreviewed one.
- A decisions table or surface. Zero code exists; building it is a product
  decision, not a gap fill.
- Visual and motion treatment. E05.11 and E05.12.

## Implementation approach

Audit first, build only the gap. The mention pool was the only defect found on
the shipped path.

## Acceptance criteria

1. Comments exist as durable, attributed, per-task records with a composer, and
   this is proved by table and component, not asserted.
2. Attachments exist with server-side size, type and quota enforcement and an
   authenticated download, and this is proved by file and line.
3. Subtasks exist as real child tasks that stay out of the board, list, calendar
   and timeline views.
4. A member of the workspace can be mentioned in a comment from the first
   comment onward, without having to have commented first.
5. Decisions are reported honestly as existing or not existing, with the search
   that establishes it.
6. No comment, attachment, subtask or assignee reaches an unauthenticated
   surface, proved by the public projection allowlist and its test.
7. Nothing in this task adds or widens an upload path.
8. `pnpm test` passes and the new behaviour is covered by a test that fails
   against the code as it stood.

## Validation plan

Same chain as E05.06: `pnpm test`, `pnpm typecheck`, `npx eslint`, `pnpm ds:check`,
plus the fail-before mutation on the roster contract test.

## Evidence required

`evidence/E05.07-task-detail-experience.md`.

## Risks

- **Decisions are named in this task's own title and do not exist.** Marking
  this task complete without saying so would misrepresent the epic.
- The attachment path is sound on the evidence read here, but it has not been
  security-reviewed. This task does not claim it has.

## Decisions required

1. **Do decisions become a real object before 1 September?** Today the only
   trace is a `"decision"` tag on three template tasks. A near-miss exists:
   `tasks.source_note_extract_body` already stores the creator-approved wording
   that produced a task and is read by no component.
2. **Do photographs belong in a couple's task detail?** Attachments accept
   images today, and the public artifact carries none. That boundary is
   currently held by a field-shape accident rather than a decision.

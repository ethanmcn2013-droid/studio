# Second adversarial fact-check — BRIEF v1.1 and the superseded ledger

Run 2026-08-03 against the corrections made after the first pass. **118 claims
checked. 22 wrong or materially misleading: 8 in the brief, 14 in the ledger.**
Eleven were already wrong when written; eleven were overtaken by parallel work
within fifteen minutes. Four further defects were found in the authorities
themselves.

**Twelve of the first pass's fourteen fixes held.** The value of this pass is
that it caught the two that did not, and that it proved the ledger was the
weakest document in the set rather than the strongest.

---

## The finding that reframes the task

The reviewer used file modification times to separate two different kinds of
error: claims that were **false when written**, and claims that were **true when
written and overtaken**. That distinction turned out to be the whole story.

Both documents were written into a tree that two other sessions were rewriting
around them. The ledger's §3 claimed to be "re-verified" and was false **six
minutes and fifty-eight seconds** after the code it described had changed.

## The rule this produced

**Never state a repository fact in a document without re-running the check in the
same minute you write it, and never describe a live working tree as though it
were a fixed artifact.** The ledger now leads with that instruction and carries
the commands to regenerate itself. A document that says "verified by grep" and
cannot be reproduced by its own grep is more dangerous than one that says nothing.

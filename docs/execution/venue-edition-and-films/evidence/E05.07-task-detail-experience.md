## AC2 — attachments

**PASSES on audit. Deliberately not touched.**

`src/server/actions/attachments.ts`:

- `:35-44` — `BLOCKED_MIME_TYPES` refuses `text/html`, `image/svg+xml`,
  `application/xml`, `text/xml`, `application/xhtml+xml` and the two Windows
  executable types. Its own comment is honest about what it is: *"Not a full
  antivirus pass; enough to block the obvious executable + stored-XSS shapes."*
- `:53-58` — `safeFilename` strips path separators and everything outside
  `[a-zA-Z0-9._-]`, then leading dots.
- `:159-188` — resolves tier and quota, enforces
  `min(quota.maxFileBytes, SERVER_UPLOAD_LIMIT_BYTES)`, then confirms the task
  belongs to the **active workspace** before writing anything.
- `:189-235` — claim-then-verify: the metadata row is inserted before the bytes,
  the workspace usage SUM includes the claim, and an over-quota or failed byte
  write deletes the claim so no orphan row or orphan bytes survive.
- `:148-150` — refuses outright in demo and review mode.
- `src/server/storage.ts:65-68` — the blob backend writes with
  `access: "private"`.

Download, `src/app/api/attachments/[id]/route.ts`:

- Re-checks the workspace on every request and returns **404, not 403**, for
  mismatched, unknown and missing — opacity by default.
- Sends `X-Content-Type-Options: nosniff`, a
  `default-src 'none'; sandbox; frame-ancestors 'none'` CSP, and
  `Cache-Control: private, no-store`.

`src/server/db/schema.ts:840-864` holds the `attachments` table;
`:869-905` holds the unified `resources` table that absorbs uploads and external
links, with the cascade explicitly hand-wired because *"libSQL over Turso
stateless HTTP does not fire them reliably."*

**This task built nothing here and changed nothing here.** The instruction was
that if attachments do not exist, say so rather than build an insecure upload
path. They do exist, with more control than a fresh path would have had on day
one. **The correct next step is E08.07 reviewing this path, not E05.07 adding a
second one.** Two questions worth handing over: the mime check reads
`file.type`, which is client-supplied, and there is no content sniff behind it;
and the blocklist is a denylist rather than an allowlist.

## AC4 — a member can be mentioned from the first comment onward

**FAILED on audit. Built.**

The defect: `conversation-feed.tsx` typed `assigneeIds` as an optional prop
defaulting to `[]`, and the mention pool was `[...assigneeIds, ...commentAuthors]`.
`task-detail.tsx` **never passed `assigneeIds`**. So the pool was: people who had
already commented on this task, and nobody else.

In a fresh wedding workspace that is the empty set. **A couple could not mention
each other until one of them had already commented** — and the point of the
first comment is usually to reach the other person. Assigning the task did not
help, because the assignee list was never handed down.

Built:

- `conversation-feed.tsx` now reads `useWorkspaceMembers()` and builds the pool
  as members, then assignees, then past speakers. Members lead because that is
  who the writer can actually reach; assignees and past speakers are kept so a
  person who has since left still resolves in an old thread. Member names win
  over the seed `USERS` proxy so a real Clerk id resolves to a real name.
- `task-detail.tsx` now passes `assigneeIds={task.assignees}`.

The downstream mechanism was already correct and was not touched: names carry
into the posted body as `@Name` and the server's existing mention scan turns
those into notifications.

## AC6 — private collaboration: nothing here reaches a public or venue surface

**PASSES on audit. This is the programme's central promise and it holds.**

`src/lib/public-task.ts` is a field-by-field allowlist for every unauthenticated
task response, with its own reason written in: *"Keep this field-by-field so
adding a private column to Task cannot silently publish it through `/p`,
`/embed`, or `/share`."* It emits `id`, `title`, `lane`, `priority`, and
optionally `due`, `boardColumnKey`, `tags`. **Comments, attachments, subtasks,
assignees, description, contact and amount are all absent.** Held by
`src/lib/public-task.test.ts:33` — "public task projection is a stable
allowlist" — which is in the `pnpm test` chain.

Venue-facing egress is `src/app/api/internal/partner-stats/route.ts`. It returns
four scalars: `codesRedeemed`, `redeemed30d`, `reachedBoard`,
`mostRecentRedemptionAt`. No task, comment, attachment, subtask, name or title.

**Two things that are not this task's to fix but must not be papered over.**
The count returned by that endpoint carries no small-cell floor, which is the
R-027 shape on a second endpoint. And R-031 stands: `/p` is deliberately
indexable. Neither touches the fields above, because those fields never leave
the allowlist. Both belong to WP-07 and WP-05.

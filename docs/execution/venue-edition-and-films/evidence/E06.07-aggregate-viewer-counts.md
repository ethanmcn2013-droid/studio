# E06.07 — aggregate viewer counts, and the two things that were naming people

Evidence for E06.07. Written 2026-08-03 in worktree `_wt-wp14` (app, branch
`claude/wp14-timeline`, stacked on the unmerged `claude/wp08-couple`). Criteria
were written before the assessment. Every claim below carries a path and a line
as it stands in that worktree, or a command and its real output.

**Read the concurrency note at the end before trusting any file-level claim.**
This worktree was shared with at least one other live Wave 4 session while this
work ran.

---

## The headline in one paragraph

The counting mechanism was already good and is kept. What was wrong was the two
places the number came out. `artifact-studio.tsx` rendered `qualifiedViewCount`
next to `lastQualifiedViewAt` at day precision, so at a count of one the couple's
own page told them which single guest had read it and on what day; and
`layout.tsx` loaded Google Analytics on every route the couple can share, so a
wedding guest was measured by a third-party US provider before being asked
anything. Both are closed. The suppression rule now lives with the value, both
render sites go through it, the four couple-facing routes are excluded from GA4
at the component seam and at an enforced CSP, and a registered contract test
fails if any of the three layers is deleted.

## Criterion-by-criterion

### 1. No third-party analytics on `/p`, `/s`, `/share` or `/embed` — **MET**

Three layers, and the criterion names why a Playwright assertion cannot carry
this: the e2e suite runs with `VERCEL_ENV=preview`, and `GoogleTag` renders only
when `VERCEL_ENV === "production"`. A browser assertion that GA is absent on `/p`
passes today and would keep passing if the exclusion were deleted. It would prove
nothing. So the assertion is on source text, and the test file says so in its own
header.

**Layer 1 — the boundary.** `src/lib/public-analytics-boundary.ts` names the four
routes and matches a root exactly or as a path prefix, so `/pricing` and
`/sitemap.xml` are unaffected. Deliberately separate from `isBareArtifactPath`,
which answers a different question and governs `src/proxy.ts`; folding them
together would silently change `/p`'s runtime.

**Layer 2 — the component seam.** `src/components/analytics/google-tag.tsx`:

```
if (isAnalyticsExcludedPath(pathname)) return null;
if (!enabled || isBareArtifactPath(pathname)) return null;
```

The order is asserted. The exclusion is evaluated **before** the `enabled` flag,
so turning GA on in a new environment cannot turn it on for a couple's page.

**Layer 3 — the CSP.** `next.config.ts` `noThirdPartyAnalyticsCsp()` emits an
**enforced** `Content-Security-Policy` for `/p` and `/share`, and a second one
for `/embed` carrying `frame-ancestors *`. It is deliberately a partial policy:
`script-src`, `connect-src`, and three hardening directives identical to the
baseline. It sets no `default-src`, so it can only restrict what a page executes
and connects to, never what it may load or render. The builder throws at config
load if a Google host survives an edit.

**Fail-before mutation, run verbatim.** With `if (isAnalyticsExcludedPath(pathname)) return null;`
deleted from `google-tag.tsx`:

```
✔ the analytics boundary names exactly the four couple-facing routes
✔ the predicate matches a route root and its children, and nothing else
✖ GoogleTag refuses the excluded routes before anything else
✔ no excluded route tree renders the tag itself
✔ the per-route CSP for /p, /share and /embed carries no analytics host
✔ no owner surface renders a raw qualified view count
✔ the last-viewed timestamp is never rendered at day precision
✔ the suppression floor lives with the value, not with a caller
ℹ tests 8  ℹ pass 7  ℹ fail 1
```

Restored from a copy taken before the mutation; `pass 8 fail 0` on re-run and
`git status` shows only the intended change.

**A trap worth recording.** The first attempt at this mutation used `'\n'` in a
string replace and silently did nothing on a CRLF file — and the test still
passed, which would have read as "the mutation was applied and the test did not
catch it". It was caught because the mutation script did not assert that it had
changed anything. Every mutation script here now fails loudly if the replace is a
no-op. This is the same defect class as the three unregistered privacy tests
Wave 3 found.

**What is NOT claimed.** `/s` already carried an enforced, analytics-free policy
before this task (`audienceArtifactCsp`, `connect-src 'self'`, plus an
`X-Robots-Tag` header). That is verified and recorded, not rebuilt. And the
baseline site-wide CSP still ships **Report-Only** unless `SIGNAL_ENFORCE_CSP` is
set; whether that variable is set in production is not verifiable from this
worktree. The couple-facing policy above does not depend on it — it is emitted
enforced regardless — but the general posture claim does.

### 2. First-party, aggregate, no identifiers durably stored — **MET, existing evidence**

Assessed, not rebuilt. `src/modules/timeline/lib/qualified-view.ts`:

- `parseQualifiedViewPayload` sorts the key list and rejects anything that is not
  exactly `{sessionId, visibleForMs}`: *"View receipt contains unsupported
  fields"*. Referrers, user agents, IPs and raw tokens cannot drift in through
  permissive spreading.
- `hashQualifiedViewSession` digests `sha256(publicationId \0 sessionId)`, so one
  viewer cannot be correlated across two publications.
- `qualifiedViewRequestEligibility` rejects cross-origin, wrong `Sec-Fetch-*`,
  prefetch, bot user agents and non-JSON. Its own comment states that none of
  those values is returned or written.
- Dwell must be between 2000 ms and 60000 ms.

`server/qualified-view-store.ts` writes only `(publicationId, sessionHash,
createdAt, expiresAt)` and deletes expired receipts opportunistically at a 30
minute retention. The aggregate is a counter on the publication row.

This is a genuinely well-built mechanism and the correct decision was to leave it
alone.

### 3. The suppression rule is a property of the value — **MET**

`src/modules/timeline/lib/viewer-count.ts`. `presentViewerCount` returns a
discriminated union and **never a number**:

```ts
| { state: "withheld"; reason: "below_floor"; note: string }
| { state: "shown"; label; countLabel: string; lastViewedLabel: string | null }
```

`countLabel` is pre-rendered, so no downstream formatter has an integer to
reformat — the fix shape R-028 asks for, where the threshold cannot be forgotten
by a caller. The floor is validated (`< 1` or non-integer throws), so a caller
cannot pass its way underneath it. A malformed count throws rather than renders.

**Fail-before mutation.** `VIEWER_COUNT_FLOOR` lowered from 5 to 1:

```
✖ every count below the floor is withheld, and they are indistinguishable
✖ the withheld note never states the bound
✖ a withheld presentation carries no timestamp of any kind
✖ the list summary is silent below the floor and never says why
✖ the floor is not D-011's venue-cohort threshold of 3
ℹ tests 10  ℹ pass 5  ℹ fail 5
```

Restored; `pass 10 fail 0`.

### 4. Below the floor the surface says nothing about the data — **MET**

Counts of 0, 1, 2, 3 and 4 produce **byte-identical** output. The test serialises
each presentation and compares the JSON, because anything that differs between a
count of zero and a count of one is the de-anonymisation this module exists to
remove.

The withheld copy is asserted to contain no digit and no bound phrasing:

> Views appear here once enough people have opened the link. Below that, a count
> would point at one person.

It states the rule, not the value. R-027's mitigation says never render "fewer
than 3", and that is enforced by a regex over the string rather than by
convention.

**Stated plainly, because it is a real residual.** Withholding does tell the
couple that the count is below the floor. That is unavoidable in any design that
ever shows a number, and it is a far weaker disclosure than the count itself: the
couple cannot tell 0 from 1 from 2, and cannot tell when. Removing the timestamp
and the small integer removes the vector that actually names a guest. It is
recorded as accepted, and it is decision 2 in the task spec.

### 5. `lastQualifiedViewAt` no longer sits beside a count at day precision — **MET**

The defect, verbatim from the tree before this change
(`src/modules/timeline/app/audience/artifact-studio.tsx:59-67`):

```tsx
<dt className={styles.statLabel}>Timeline views</dt>
<dd className={styles.statValue}>{publication.qualifiedViewCount.toLocaleString("en-GB")}</dd>
...
<dt className={styles.statLabel}>Last viewed</dt>
<dd className={styles.statValue}>{displayDate(publication.lastQualifiedViewAt)}</dd>
```

`displayDate` used `{day: "numeric", month: "short", year: "numeric"}`. That is
"Timeline views 1 · Last viewed 3 Aug 2026" — the pair D-033 names.

Now: one stat cell. Above the floor it shows the count and, as a caption, "Last
opened in August 2026". The `Intl` formatter is month and year only, so a single
visit cannot be pinned to a day. Below the floor neither value exists on the
object at all.

**Fail-before mutation.** Reintroducing the label `Last viewed` alone was enough:

```
✖ the last-viewed timestamp is never rendered at day precision
ℹ tests 8  ℹ pass 7  ℹ fail 1
```

### 6. Every render site goes through the presenter — **MET**

Two sites, and the second is the one that would have been missed.
`audience-manager.tsx:353` rendered `{publication.qualifiedViewCount.toLocaleString("en-GB")} view(s)`
in a dense list row. It now calls `viewerCountSummary`, which returns `null`
below the same floor and the row simply omits the clause. A list that leaks what
the detail page conceals is the R-028 shape wearing a different costume.

The contract test asserts, for both files, that they import the presenter, do not
call `.toLocaleString` on the count, do not render the integer directly, and do
not pass their own `floor:`.

### 7. The floor is a founder decision, not D-011's — **MET as a recorded decision, NOT ratified**

Shipped at **5**, in a named exported constant whose comment says explicitly that
it is not D-011's 3 and 5, because those count sponsored workspaces across a
venue and were ratified for a different population. A test asserts that 3 and 4
are withheld, so a future edit that quietly adopts the venue number goes red.

**This is a recommendation awaiting ratification, not an approval.** It is
decision 1 in the task spec.

### 8. `/p` and `/share` have no first-party counter — **STATED, NOT BUILT**

Honest answer: there is no equivalent counter on `/p`, and the `/share` counter
is not fit to be one.

- `/p` has no view counting of any kind.
- `/share` has `share_links.visits` (an integer bumped per open) and
  `share_link_visits`, a **per-visit** log carrying `visitedAt` and
  `userAgentHint` — the first 60 characters of the user agent. Nothing renders
  either today (`grep` for `userAgentHint` returns only `schema.ts` and
  `queries.ts`). A per-visit timestamped log with a device hint is the opposite
  of an aggregate, and it is worse than what this task just removed from `/s`.

Nothing was built on `/p` or `/share`, because building a counter there would
pre-empt the founder question about which surface is the couple's keepsake.
`share_link_visits.user_agent_hint` is raised as decision 3: delete the column,
or keep it and disclose it. It is not left implied.

## The concurrency note, which is not a footnote

This worktree, `_wt-wp14`, was being edited by at least one other live Wave 4
session for the whole of this one. Observed directly:

1. `next.config.ts` was independently rewritten by another session **three
   times** while this package was editing it, twice implementing the same R-032

   promoted to make, and the privacy control does not need it.
2. A duplicate `0027` migration for the same `/p` search-visibility column was
   created by both sessions within minutes. This package deleted its own
   (`0027_workspace_search_visibility.sql`) and its ledger and journal entries.
   **At the time of writing, `src/server/db/schema.ts` carries
   `searchVisibilityOptedInAt` and no migration file for it exists on disk.**
   That must be reconciled before merge.
3. `pnpm experience:test` could not be run at all. It binds port 4342 and the
   other session held it. Two attempts, both refused before a browser started.

None of this invalidates the E06.07 result — the files this package owns are
new, and the contract test pins them — but a verifier re-running these commands
may see a different tree, and should re-run rather than trust.

# E06.04 — milestone navigation, and the transition that has nothing to transition to

Evidence for E06.04. Written 2026-08-03 in worktree `_wt-wp14` (app, branch
`claude/wp14-timeline`). Criteria were written before the assessment.

---

## The headline in one paragraph

The navigation half of this task is built, complete and better than the task
title implies, and rewriting it would have been the exact failure D-015 Q2 warns
about. The photograph-and-story half cannot be started, because the published DTO
carries neither a photograph nor a story and cannot be made to without E06.02 and
E06.03. The audit found one real defect and it was in copy, not behaviour: two of
the three sentences under a milestone title used "journey" as a noun, on a
couple's wedding page, which the brand voice bans. That is fixed. The axe
criterion could not be verified in this session and is reported as unverified.

## Criterion-by-criterion

### 1. The dependency is stated, and no placeholder frame ships — **MET**

`src/modules/timeline/lib/audience-timeline.ts:56` — `ITEM_KEYS` is exactly
`new Set(["publicId", "title", "date", "state"])`. `attachments` and `description`
are in `FORBIDDEN_KEYS` (`:57-74`), and the validator's `exactKeys` throws
`"<path>.<key> is not allowlisted"` for anything outside the set.

So there is no photograph and no story on the boundary, at any layer. A
transition built now would animate from a milestone to an empty frame. Nothing
was built. `MilestoneDetail` renders what the DTO actually carries — status,
title, one line of prose, and two facts — and no empty slot exists to leave a
gap. That is criterion 4 as well, and it is satisfied structurally rather than by
a fallback branch, which is the stronger form.

### 2. The keyboard contract survives unchanged — **MET, existing evidence**

`src/modules/timeline/components/artifact/timeline-artifact.tsx`:

| Contract | Where |
|---|---|
| Left and Right between milestones | `handleKeyDown:435-440` |
| Home and End to jump | `:441-446` |
| Escape closes detail | `:447-450` |
| Enter and Space select | native `<button>` `onClick:574-578`, not re-implemented |
| Roving tabindex | `tabIndex={index === boundedFocusIndex ? 0 : -1}` `:565` |
| `aria-expanded` on the selected point | `:568` |
| `aria-controls` pointing at the detail panel | `:569` |
| Polite live region announcing open and closed | `:604-608` |
| Instructions bound with `aria-describedby` | `:536`, text at `:488-490` |
| Per-point label with position | `:570`, "Milestone N of M" |

Nothing here was changed by this task. Recorded as passing, not rebuilt.

Worth stating because it reads as a bug and is not: the arrow keys move **focus**
and do not change selection. Selection is a deliberate act, Enter or Space. That
is the correct roving-tabindex pattern for a list where opening a panel is a
distinct decision, and the instruction text at `:489` describes exactly that
behaviour rather than a different one.

### 3. `prefers-reduced-motion` is honoured — **MET, existing evidence**

`useArtifactReducedMotion:56-60` reads Motion's media-query hook and gates it
behind React's hydration snapshot, so the server render and the first client
render always choose the same motion props and the same subtree. That is a real
correctness detail, not decoration.

It is then honoured everywhere it matters, and not only in the obvious place:

- `MilestoneDetail:349-352` — no enter animation, no exit animation, duration 0.
- `Journey.focusPoint:431` — `scrollPointIntoView(bounded, reduceMotion ? "auto" : "smooth")`.
  Programmatic smooth scrolling is motion too, and this is the one most
  implementations miss.
- `TimeLens:171-206` — both the metric face and its sweep.

### 4. A milestone with no photograph degrades cleanly — **MET**

See criterion 1. There is no photograph slot to leave empty, so there is no
layout shift and no empty frame. This will need re-asserting once E06.03 lands,
because at that point the degrade path becomes a real branch rather than a
structural fact.

### 6. `detailNote` passes the brand voice — **MET, and this was the defect**

Before, verbatim:

```ts
if (point.state === "complete") return "This milestone is part of the story so far.";
if (point.isNext) return "This is the next point on the shared journey.";
return "This milestone comes later on the shared journey.";
```

Two of the three use **"journey" as a noun**, which the brand voice bans
outright. This is not an internal string or a code comment: it is the sentence
under a milestone title on a sponsored couple's public wedding page, rendered at
`:357`, and it would have shipped into the film.

After:

```ts
if (point.state === "complete") return "This one is already behind you.";
if (point.isNext) return "This one is next.";
return "This one comes later.";
```

Shorter, plainer, and it no longer restates the status label that already renders
directly above it at `:355`. Kept rather than deleted, deliberately, because it
is the slot a real milestone story lands in once E06.02 and E06.03 give the DTO
something to carry — and the note in the source says so, so the next person does
not delete it as filler.

No test asserted the old strings (`grep` for "shared journey" across `src/`,
`e2e/`, `experience/`, `scripts/` returned only the component itself), so the
change breaks nothing. That was checked before editing, not after.

## 1. The headline, first, because it changes what this task can be

**Keepsake exists as a library and does not exist as a product.**

Verified 2026-08-04 in `_wt-integrate` @ `a78f3c3`:

```bash
grep -rn "resolveCoupleAccess\|buildKeepsakeExport" src/ | grep -v "lib/keepsake"
# (no output)
```

`src/lib/keepsake/lifecycle.ts` and `src/lib/keepsake/export.ts` are real, well
tested, and called by nothing. `pnpm test` covers them (*"the term ending
produces Keepsake, not a lockout"* passes). There is no route, no settings
surface, no export button, no phase indicator, and no copy in the app that a
couple could ever reach. The only other mentions of the word in the tree are a
comment in `robots.ts` and a comment in
`src/components/app/settings/sections/billing.tsx` that still asserts the
feature does not exist at all.

So E15.05 cannot test Keepsake end to end. What it can do, and what section 4
does, is test the four things that do exist and state the Keepsake position
truthfully.

**This is not urgent in calendar terms.** No sponsored couple reaches the end of
term before 2028. **It is urgent in promise terms.** The Benefits Charter and
D-010 point 3 put Keepsake in front of a venue in September, and a venue repeats
it to couples. R-020 is exactly this hazard with the venue as the speaker.

### Step 2 — Indexing, against production and not against the branch

  ```bash
  curl -s https://app.signalstudio.ie/robots.txt
  curl -sI https://app.signalstudio.ie/p/<published-wedding-slug> | grep -i x-robots
  ```

- **Expect:** `Disallow: /p` in robots.txt, and `noindex` on the wedding page.
- **Pass:** both.
- **Fail:** STOP before publishing anything for a real couple.
- **Result 2026-08-04:** **FAIL on robots.txt.** Production disallows `/app`,
  `/s`, `/share`, `/redeem`, `/welcome`, `/api`. `/p` is not among them. The
  branch fix is verified by four passing tests and is undeployed:

  ```
  ✔ a wedding workspace is detected in /p metadata
  ✔ the wedding branch sets index:false and follow:false
  ✔ the wedding branch also suppresses archiving and snippets
  ✔ /p is disallowed in robots.txt as well as noindexed
  ```

  The page-level check could not be run: it needs a published wedding slug and
  none exists to test against.

### Step 3 — Revocation must be immediate

**Not run. Needs a published workspace.**

- **Do:** create a `/share/<token>` link, load it, revoke it, load it again in a
  fresh session.
- **Expect:** the second load fails.
- **Fail:** any cached render surviving revocation is a critical stop. Note
  R-033 alongside: `share_links.token` is a plaintext primary key resolved by
  raw equality, while the Timeline path hashes with a unique index and a
  constant-time compare. The two paths do not have the same properties.

### Step 4 — Unpublish must reach every route

**Not run.**

- **Do:** publish, then call unpublish, then request `/p/<slug>`,
  `/s/<token>`, `/share/<token>` and `/embed/<slug>`.
- **Expect:** all four stop rendering.
- **Fail:** `/embed` still rendering after unpublish is a critical stop. The
  route exists for a blogger to iframe a workspace into a page the couple has
  never seen (R-033), so a stale embed is a redistribution the couple cannot
  see and cannot stop.

### Step 5 — The viewer count

**Not run.**

- **Do:** load the published page from a clean session, from the couple's own
  session, and with a crawler user agent. Read the count after each.
- **Expect:** only the qualified view increments it.
- **Fail:** the couple's own loads or a crawler moving the number. A count a
  couple cannot trust is worse than no count.

### Step 6 — The export the couple owns

**Not run.**

- **Do:** produce the export from the couple's account and open it without
  Signal Studio.
- **Expect:** readable content, the couple's own material, no dependency on the
  service to read it.
- **Fail:** an export that needs the product to open is not an export.

### Step 7 — State the Keepsake position honestly

**Only the founder can settle this.**

- **The true statement today:** the Keepsake rules and export format are written
  and tested as a library. No couple can reach them. No sponsored couple reaches
  the end of term before 2028.
- **The permitted wording**, whichever way the decision goes: free, read-only,
  indefinite access while the service exists, with a one-click export the couple
  owns. **Never** "forever", "for life", "in perpetuity", and never a storage
  guarantee (D-010 point 3, D-021's restatement, R-020's prohibited-claims list).
- **The decision:** ship a minimum surface before Cohort 1, or restate the
  promise in the charter and the agreement before signature. There is no third
  option that is honest, because the charter is signed in September and a venue
  repeats what the charter says.

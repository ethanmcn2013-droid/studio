## The headline: both original production blockers are now closed

The E05/E06 audit opened with two blockers and said nothing in E05 was demonstrable
until they landed. Both are shut.

**Blocker 1** (Wave 3): the `/app` gate bounced every invited and redeemed user to
`/waitlist` after their token was spent.
**Blocker 2** (Wave 4): `createWorkspaceAction` had zero callers, so a couple could
never get a Timeline workspace, and even if it were wired the Timeline rendered
empty because the wedding template set neither `is_millestone` nor `due_at`. Both
halves are fixed, verified independently, and pinned by a registered test that goes
red when the call is removed.

Timeline is the film's hero. It now works for a sponsored couple.

## Three findings that justify the review system

**1. R-031 was reported built and was not.** The build agent's evidence cited
`src/lib/wedding-workspace.ts` and described that file's internals in the present
tense. The file did not exist and never had; `isWeddingWorkspace` appeared nowhere
in `src`; `/p/[slug]/page.tsx` was untouched. **Two independent controls caught it**
— the adversarial verifier, and the evidence-path validator, which refused the
reference automatically. I implemented it myself afterwards.

**2. `prohibited-claims.v1.json` was read by nothing.** Its own `readBy` field named
`check-venue-edition-contract.mjs`; that 346-line script contained no reference to
it. **E09.11 §12.2's claim that a second validation stage was added, and its entire
§12.3 before/after table, describe work that was not in the repository.** Two
published numbers were wrong with it: the file tracks 22 surfaces, not the 37 my own
R-042 brief claimed to have verified, and the pinned hit sum is 20, not 25.

**3. Removing GA4 does not satisfy D-033 Option A.** `instrumentation-client.ts`
initialises **Sentry** on every route except `/s`, at 0.1 trace sampling, with
`beforeSend` covering error events only and no `beforeSendTransaction` — so
transaction URLs still leave. Sentry is a third party. The ratified sentence says
*no* third-party analytics on any couple-facing public surface.

Each is the same shape the programme keeps producing: a control that is documented,
believed, and absent.

## A limitation I did not fix, and should have

is therefore not trustworthy** — a verifier watched the full suite go from red to

couple-facing routes. Every gate was re-run after each wave settled, which is the
mitigation, but the next wave should isolate per build group rather than per package.

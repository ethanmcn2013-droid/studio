# E06.02 — per-milestone visibility states, audited and evidenced

Written 2026-08-03 in worktree `_wt-wp14` (app, branch `claude/wp14-timeline`).
Acceptance criteria were written before the assessment.

**Two of the four states ship and are proven here. Two do not exist at any
layer and are recorded as not built.** Nothing in this document claims legal
approval or GDPR compliance (D-016).

---

## The four states, honestly

| State | Exists | Where |
|---|---|---|
| **Private** | yes, by two mechanisms | omission from `selectedSourceIds`; `node_overlays.hidden` refused at selection |
| **Title and date** | yes, and it is the default | `timeline_publication_items.calendar_date` nullable; the DTO omits the key |
| **Image** | **no** | no `ITEM_KEYS` entry, no validator branch, no column, no byte path |
| **Short story** | **no** | same |

---

## Criterion-by-criterion

### 1. Private, proven twice — **MET**

**Mechanism one, omission.** Publication is opt-in per milestone.
`createAudiencePublication` (`src/modules/timeline/server/audience-timeline.ts:135`)
copies only the nodes named in `selectedSourceIds` into
`timeline_publication_items`, capped at 100 and at one project. A milestone the
couple does not select is never copied, so it cannot be published by a later
bug in the read path — it is not in the published table.

```
✔ E06.02 · private · a milestone left out of the selection is never copied
```

The fixture holds four milestones in one workspace. One is selected. The
resolved DTO's item titles are exactly `["The ceremony"]`, and the serialised
payload does not contain `"Agree the budget with Dad"`.

**Mechanism two, refusal.** `audience-timeline.ts:159`:

```ts
if (!node || node.hidden) throw new TypeError("A selected milestone is not available in this workspace");
```

So a milestone the couple has hidden in the private Timeline cannot be published
even if its id is submitted directly.

```
✔ E06.02 · private · a hidden milestone is refused at selection
```

**Fail-before mutation, run verbatim.** With `|| node.hidden` deleted from
line 159:

```

✔ E06.01 · a shared name carrying a home address never reaches a public page
✔ E06.01 · real couple names still pass, and other audiences keep the old rule
```

Exactly the one assertion went red. The file was restored from a copy taken
before the mutation.

### 2. Title-and-date, proven on a serialised DTO — **MET**

The data layer is `node_overlays.date_override` with an explicit three-way
intent, `inherit | date | undated`, persisted through the
`__signal_timeline_undated__` sentinel
(`server/db/timeline-queries.ts:77-99`). An `undated` milestone resolves to a
null `targetDate`, is frozen with `calendarDate: null`, and the DTO builder
omits the key: `if (item.date !== undefined)` at
`lib/audience-timeline.ts:221`.

```
✔ E06.02 · title-and-date · an undated milestone carries no date key
```

In one payload, "Find the dress" has keys exactly `publicId, state, title` and
`"date" in item` is false, while "The ceremony" has exactly
`date, publicId, state, title`. So the state is a genuine omission, not an empty
string or a placeholder.

**This is also the default.** A publication created from milestones with no
target date publishes title-only without the couple doing anything, which is the
more private default and matches the brief.

### 3. Freeze semantics — **MET as stated, and the distinction is drawn**

**Proven.** The published payload is read from `timeline_publication_items`
only. `resolveAudienceTimeline` selects five columns from that table
(`server/audience-timeline.ts:797-809`) and touches no node, overlay or task
table. Every assertion in this suite reads through that path.

**Read, not behaviourally proven in this package.** The copy is taken inside the
create transaction at `audience-timeline.ts:210-244`, and
`refreshAudienceDivergence` (`:678`) marks `divergedAt` when the source changes
without altering the published copy. The E05.08 suite already asserts the
published projection carries presentation fields only. A test that mutates a
source node and re-resolves the token was **not** written here, so the claim
"changing a milestone after publish does not change the live page without a
republish" is supported by the read path and by the divergence design, not by a
behavioural assertion. Stated that way rather than claimed as proven.

The consequence for a future image state is recorded in the spec: downgrading
from image to title-and-date must clear the frozen column, not only the source,
and `/s/[token]` is `force-dynamic` with `revalidate = 0`
(`src/app/s/[token]/page.tsx:6-8`), so there is no cache window to state.

### 4. Image and short-story are recorded as not built — **MET**

What each needs, in order:

1. **A column on `timeline_publication_items`** — `image_url`, `image_alt`,
   `image_width`, `image_height` for the first; `story_body` for the second.
2. **An `ITEM_KEYS` entry and its own validator branch** in
   `validateAudienceTimelineDto`. Allowlisting without rebuilding would let the
   field carry anything.
3. **A public byte path with EXIF stripped** — E06.03's work, and it does not
   exist: `src/server/storage.ts` writes with `access: "private"` and the only
   read path is `src/app/api/attachments/[id]/route.ts`, which re-checks auth.
4. **A migration apply path for the Timeline database.** `drizzle-timeline/`
   contains one file, `0000_timeline_baseline.sql`. `scripts/db/migrate.mjs:465`
   reads `TASKS_DATABASE_URL` only, so the receipt-backed runner — the only
   sanctioned production path in this repo — does not reach this database at
   all.

Point 4 is the blocker and it is new to the register. It is the founder decision
on this task.

### 5. A regression guards the half-built case — **MET**

```
✔ E06.02 · image and short-story states have no representation at any layer
```

It reads `lib/audience-timeline.ts` and `server/db/timeline-schema.ts` and fails
if `ITEM_KEYS` gains an `image`, `imageUrl` or `story` key, or if
`timeline_publication_items` gains an `image_url` or `story_body` column. It is
deliberately a failing-capability guard: when either state is genuinely built,
this test goes red and has to be rewritten on purpose, with the content model
updated in the same change.

### 6. No string offers what is not built — **MET**

The owner studio renders title, date and state per item
(`src/modules/timeline/app/audience/audience-manager.tsx`). There is no image
control, no story field and no "coming soon" copy. Nothing in this document or
the spec describes either state as available.

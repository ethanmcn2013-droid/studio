## 3. What the audit of the checkpoint found

The 2026-08-03 checkpoint commits `a5324b3` (app) and `7cb50d5` (studio) carried
this work unverified. Three findings.

### 3.1 A green that measured an empty set — FIXED

The app contract's `repo_images` budget reported `0 KB · ok`. Its stated basis
was "No image in this repository's public directory exceeds 200 KB today".

That sentence is true. It is also true of an empty set, and `app/public`
contains five SVGs and one directory and **no raster image at all**. The budget
measured nothing and reported a pass — the same failure the whole contract
exists to replace, reproduced inside it.

Fixed two ways:

- Every measured number now carries the population it was computed over. A
  population of zero exits 3 with `NOTHING MEASURED` unless the contract
  declares the emptiness with a reason, and even then it prints
  `no data (declared)`, never `ok`.
- A missing `imageRoot` directory now exits 3 instead of walking to zero, so a
  typo in the contract cannot produce a passing measurement.

The app contract now carries the declaration, and the honest sentence:

> `app/public` contains five SVGs and one directory and no raster image at all,
> verified 2026-08-03 … An earlier version of this contract described the same
> fact as "no image exceeds 200 KB", which is true of an empty set and reads as
> a passing measurement. That is the failure this declaration exists to prevent.

### 3.2 The checker's own rules were never exercised — FIXED

`--self-test` now proves twelve rules with no build required, and runs in CI
before the measured check:

```
check-performance-budgets --self-test
  ok    a value under budget passes
  ok    a value under budget reads ok
  ok    over budget but under ceiling does not fail the build
  ok    over budget is stated, not hidden
  ok    over the ceiling is a breach
  ok    exactly at the ceiling is not a breach
  ok    an empty population is an error, not a pass
  ok    an undeclared empty population produces no green row
  ok    a declared empty population is allowed
  ok    a declared empty population never reads ok
  ok    a contract budget the script cannot produce is an error
  ok    a measurement with no population count is an error

check-performance-budgets: self-test ok
```

### 3.3 `pnpm performance:measure` was left live — FIXED, with a caveat

## 6. The gate criterion cannot be satisfied as written

The `data` release gate says, of E08.10:

> Performance budgets are measured on the surfaces that carry the product's
> claim: the shared Timeline on a mid-range mobile over a throttled connection,
> the portal Overview, and the couple briefing. `pnpm budgets:check` and
> `pnpm performance:measure` produce recorded numbers against stated budgets and
> a regression fails the build.

Three problems, all verified:

1. **"a mid-range mobile over a throttled connection"** needs a device profile
   and network throttling. There is no device lab, no Lighthouse CI job and no
   RUM provider, and adding one is a spend decision under a zero budget.
2. **`pnpm budgets:check`** exits 2 with four missing measurement categories.
3. **`pnpm performance:measure`** measured a repository layout that stopped
   existing on 2026-07-31, and is now retired.

What this task delivers instead is bundle-weight enforcement that runs on every
pull request and fails the build. That is less than the gate asks for and more
than existed this morning. Closing the difference is a change request, and it is
raised as one rather than the words being quietly reinterpreted.

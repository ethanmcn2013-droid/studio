---

## 1. What only a human can do

Watch. A watch sheet works because somebody fills it in daily during the window,
notices the second time something looks odd, and acts. No amount of tooling
substitutes for that during a two-week window with one operator.

## 2. The watch sheet

| Surface | Check | Frequency | Threshold | Action on failure |
|---|---|---|---|---|
| Product health | `GET /api/health/digest` returns 200 | every 15 min, automated | one failure | alert the founder; if two consecutive, treat as an incident |
| Error rate | Sentry events by hour | daily read | any new error class touching redeem, publish or attachments | investigate same day |
| Commercial pages | HTTP status sweep of every URL named in outbound material | daily during the window | any non-200 | fix before the next send |
| Outbound email | delivered and replied, per send | per send | any bounce, or delivery below expectation | check the address, then the domain reputation |
| Redemption path | count of first-party loads of the redemption page | daily | a code sent and never opened after 72 hours | personal follow-up, not a reminder email |
| Films and portal assets | the linked asset loads and plays | daily | any failure | pull the link from outbound material immediately |

**One definition matters more than the rest.** `opened` is a first-party load of
the redemption page, **never an email open** (D-026, R4). Email-open pixels are
unreliable, they are blocked by default on most clients, and building a decision
on them produces confident nonsense.

## 3. The automatable checks

### C1 — The route sweep

- **Run:**
  ```bash
  for u in https://signalstudio.ie/venues \
           https://signalstudio.ie/venues/questions \
           https://signalstudio.ie/venues/what-you-see \
           https://signalstudio.ie/venues/privacy \
           https://signalstudio.ie/privacy \
           https://signalstudio.ie/terms \
           https://signalstudio.ie/security \
           https://app.signalstudio.ie/api/health/digest ; do
    printf "%-48s " "$u"; curl -s -o /dev/null -w "HTTP %{http_code}\n" --max-time 20 "$u"
  done
  ```
- **Result 2026-08-04:**

  ```
  https://signalstudio.ie/venues                   HTTP 200
  https://signalstudio.ie/venues/questions         HTTP 404
  https://signalstudio.ie/venues/what-you-see      HTTP 404
  https://signalstudio.ie/venues/privacy           HTTP 404
  https://signalstudio.ie/privacy                  HTTP 200
  https://signalstudio.ie/terms                    HTTP 200
  https://signalstudio.ie/security                 HTTP 200
  https://app.signalstudio.ie/api/health/digest    HTTP 200
  ```

  **Three failures.** All three pages exist in the studio integration branch and
  none is deployed. This is exactly the class of failure the sweep exists to
  catch, and it is already present before the window opens.

## 4. What the window may not measure

- **No third-party analytics on couple-facing surfaces while R-032 is open.** A
  wedding guest measured by a US analytics provider before being asked is the
  exposure, and pointing more measurement at those pages during the window makes
  it worse rather than better.
- **No venue-attributable behavioural count below the suppression floors**, in
  either direction. 1 of 40 and 39 of 40 are equally identifying.

## 2. The script

### Step 1 — The production route sweep

- **Run:**
  ```bash
  for u in https://signalstudio.ie/privacy \
           https://signalstudio.ie/terms \
           https://signalstudio.ie/security \
           https://signalstudio.ie/venues \
           https://signalstudio.ie/venues/privacy \
           https://signalstudio.ie/venues/questions \
           https://signalstudio.ie/venues/what-you-see \
           https://app.signalstudio.ie/api/health/digest ; do
    printf "%-50s " "$u"
    curl -s -o /dev/null -w "HTTP %{http_code}\n" --max-time 20 "$u"
  done
  ```
- **Expect:** 200 on every route a venue or couple can be sent to.
- **Pass:** all 200.
- **Fail:** any 404 on a route named in a proposal, an email or a pack is a
  release-blocking gap.
- **Result 2026-08-04:**

  ```
  https://signalstudio.ie/privacy                    HTTP 200
  https://signalstudio.ie/terms                      HTTP 200
  https://signalstudio.ie/security                   HTTP 200
  https://signalstudio.ie/venues                     HTTP 200
  https://signalstudio.ie/venues/privacy             HTTP 404
  https://signalstudio.ie/venues/questions           HTTP 404
  https://signalstudio.ie/venues/what-you-see        HTTP 404
  https://signalstudio.ie/venues/proposal            HTTP 404
  https://app.signalstudio.ie/api/health/digest      HTTP 200
  ```

  **PARTIAL FAIL.** The three suite legal pages and `/venues` are live. **Every
  venue sub-page is missing in production.** All of them exist in the studio
  integration branch (`_wt-wp22/src/app/venues/` contains `privacy`,
  `questions`, `what-you-see`, `couple-preview`, `demo`) and none is deployed.

  This matters more than it looks. `/venues` is deployed and carries the
  ratified offer, so a venue reaching it sees the right price and then follows a
  link to a 404. The commercial surface is half live.

### Step 2 — The analytics disclosure must match the running code

- **Run:**
  ```bash
  curl -s https://app.signalstudio.ie/p/<slug> | grep -io "googletagmanager\|gtag\|google-analytics"
  curl -s https://signalstudio.ie/privacy | grep -io "google analytics\|ga4\|cookies\|consent"
  ```
- **Expect:** the notice describes what actually loads.
- **Fail:** any third-party analytics on a couple-facing surface that the notice
  does not describe.
- **Result 2026-08-04:** not run against a published couple page, because none
  exists to test. R-032 stands as recorded: GA4 renders on every route except
  bare artifact paths, with no consent gate, and the component carries its own
  admission in a comment. The integration branch excludes Sentry from
  couple-facing public surfaces, which is a related fix and not this one.
- **The decision to take:** whether GA4 runs on couple-facing public artifacts at
  all. Removing it removes the consent question. Keeping it means a consent gate
  ahead of any non-essential script and a notice written to match.

### Step 3 — The support channel

- **Run:** send a message to the published support address from an outside
  account and time the reply.
- **Expect:** it arrives, it is seen, and the reply lands inside the stated
  commitment.
- **Result 2026-08-04:** the address in code is `hello@signalstudio.ie`
  (`src/lib/product-urls.ts:66`), used on the waitlist page, the studio rail help
  link, and the account danger-zone error copy. **Not tested.** Sending a message
  on the founder's behalf is not something this session does without being asked
  for that specific action.
- **The thing to decide:** the response commitment. One founder covering 25
  venues and their couples cannot promise same-day. A commitment that is met is
  worth more than a fast one that is not.

### Step 4 — Monitoring, proven by an error that arrived

- **Do:** raise a deliberate error in production and confirm it appears in
  Sentry within the expected window.
- **Expect:** the event arrives, is attributed, and is scrubbed of personal data.
- **Fail:** a configured DSN is not monitoring. If nothing has ever arrived,
  nothing is being watched.
- **Result 2026-08-04:** `src/instrumentation.ts` and
  `src/instrumentation-client.ts` are present and `src/lib/sentry-scrub.test.ts`
  passes in the app suite. **No production event was raised or observed.** Not
  run: deliberately breaking production is not something this session does.

a venue on to is missing. That is one deploy away from fixed and it is the sort
of thing a venue notices in the first minute.

After that, three of the six items in this task's title are documents that have
never been used: the incident runbook, the rollback procedure, and the support
commitment. Each is worth one rehearsal before September, and each rehearsal
will find something. That is the point of doing it in August.

# E15.12 — seven-day and 30-day venue reviews: the script and the disclosure rules

**Task:** E15.12 · **Written:** 2026-08-04 by Claude Code (WP-22)
**Status:** a review script plus the code-level checks that govern what may be
shown. The reviews themselves were not run; no venue is onboarded.

---

## 1. What only a human can do

Hold the conversation and hear the thing the venue does not quite say. The
review script below is fifteen minutes of structure around that.

## 2. The review script, identical for every venue

Four sections, one next action, fifteen minutes.

1. **Adoption.** What the evidence shows, within the suppression rules. If the
   population is too small to describe, say the population is too small to
   describe. Do not improvise a number.
2. **Friction.** "What was annoying?" Record the answer in the venue's words.
3. **Support.** What was asked, how fast it was answered, whether the answer
   held.
4. **Next action.** Exactly one, with an owner and a date.

Day seven catches setup friction. Day thirty catches whether anything stuck.

## 3. What may be shown, and the checks behind it

### The two-sided small-cell rule (R-027)

Verified 2026-08-04 in `_wt-wp22/src/lib/account/instrumentation/suppression.ts`:

```
export function isSmallCell(value: number, population: number): boolean {
  if (value < BEHAVIOURAL_MIN_WORKSPACES) return true;
  return population - value < BEHAVIOURAL_MIN_WORKSPACES;
}
```

The module's own words: *"publishing '3 of 5' also publishes '2 of 5 did not',
and the second sentence is the one that identifies people."* And: *"A message
that says 'fewer than three' is itself the disclosure the floor exists to
prevent."*

**In a review this means:** a venue with 40 sponsored workspaces is never told
"1 used it" and never told "39 used it". Both name one identifiable couple to a
venue that knows exactly which couples it invited.

### The rate floor (R-028)

Verified 2026-08-04: `presentRate` is called on the production path
(`daily-metrics.ts:238,241`), and the old two-argument formatter
`metricRateLabel` is gone, surviving only as a comment describing what R-028 was.
Percentages now travel as a value type through `formatRateValue`, so no formatter
can construct one from two loose numbers.

### The one still open (R-029)

**The attribution unit is incoherent.** Adoption definitions count workspaces;
the attribution join runs on `redemptions.user_clerk_id`, a subject. Nothing in
the path checks that a workspace belongs to the venue. One person with two
workspaces, or one workspace with two owners, breaks the count in opposite
directions. Tasks passes an internal user id at the call site while the other
three products pass the raw Clerk id.

**In a review this means:** a number shown today could be wrong, not merely
coarse. Until R-029 is closed, prefer withholding to publishing, and say why.
"We are not showing this yet because we are not confident the number is right" is
a better sentence to a founding venue than a wrong number.

## 4. The stop rules

- **Stop** before showing any count if the eligible population is below 3, or if
  the complement is.
- **Stop** before showing any percentage if eligible activations are below 5.
- **Never** render "fewer than N" in any form.
- **Never** commit to building something for one venue. The standing answer is
  D-014 point 2: requests are logged and shape the roadmap, nothing is built for
  one venue.

## 5. The rollup

Once two or more venues have completed both reviews, produce a cross-venue
rollup naming anything two or more venues raised. That is the signal; a single
venue's friction is a data point. The rollup feeds the roadmap, not the backlog
directly.

## 7. What I would tell the founder

The privacy work behind these reviews is genuinely good now. The small-cell test
is two-sided and lives in the definition rather than in one projector, which is
the difference between a rule and a habit.

The remaining problem is correctness, not privacy. R-029 means the number could
be wrong. Fifty reviews is also the founder-capacity question in its most
concrete form: two conversations per venue across twenty-five venues, on top of
sales and onboarding, all held by one person.

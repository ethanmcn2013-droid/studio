## 2. Broken link — **MET**

Both token surfaces produce a real 404 and neither reveals whether the resource
ever existed.

| Case | Where | Evidence |
|---|---|---|
| Unknown or revoked Timeline token | `/s/[token]` resolves through `resolveAudienceTimeline`, then `notFound()` **inside `generateMetadata`**, deliberately, so the status is a real 404 rather than a soft 404 with a 200 after streaming has begun | `tasks.page.s-by-token / invalid bearer link`, passing on all four viewport projects |
| Unknown share token | `/share/[token]` | `tasks.state.share-by-token-not-found / unknown share token`, all four projects |
| Unknown route | root | `tasks.state.root-not-found / unknown route`, all four projects |

The copy at `src/app/s/[token]/not-found.tsx` is correct on the point that
matters: *"The owner may have rotated, revoked or unpublished this timeline.
Ask them for the current link."* It names four possibilities and commits to
none, so a stranger holding a guessed token learns nothing about whether a
timeline exists behind it.

## 3. Delete — **one real defect, found here, fixed here**

**The defect.** `/p/[slug]` is ISR with `export const revalidate = 60`.
`publishWorkspaceAction` and `unpublishWorkspaceAction` both call
`revalidatePath('/p/{slug}')`. **`deleteWorkspaceAction` did not.** So a couple
who deleted a published wedding workspace kept serving its cached public page —
task titles and tags, which carry guests' and suppliers' names — for up to
sixty seconds after the delete, with no row left in the database to explain it.

**The fix**, `src/server/actions/settings.ts`: read the slug before the
transaction that deletes the row, and `revalidatePath('/p/{slug}')` after it.
Unconditional on `publishedAt`, because a workspace published and later
unpublished may still hold a cached entry and revalidating an uncached path
costs nothing.

**Pinned by a registered contract test**,
`src/server/published-surface-revalidation.test.mjs`. It asserts against source
text on purpose and says so in its own header: the defect was never a logic
bug, it was a missing call, and only the wiring can catch a missing call.

**Fail-before mutation, run verbatim.** With the new `revalidatePath` line
deleted:

```
✔ the published page is cached, which is what makes the revalidation load-bearing
✖ publish, unpublish and delete all drop the cached public page
✔ delete reads the slug before the row is deleted, not after
ℹ tests 3  ℹ pass 2  ℹ fail 1
```

Exactly the intended assertion went red. The file was restored and
`git diff --stat` shows the fix as the only change: `15 insertions(+)`.

**The window, stated as the criterion requires:** publish, unpublish and delete
now all drop the public page immediately. Content edits inside a published
workspace still take up to 60 seconds, which is the ISR window and is
deliberate.

1440) are both evidenced clean, which is the accessibility criterion in E06.09
and E06.10.

**Three honest limits on this number.**

- **Every capture runs in demo mode.** `browser-contract.json` sets
  `accessMode: "demo"` and `deploymentEnvironment: "preview"`. No pass here is
  evidenced on an authenticated couple journey. `critical-fixtures.json`'s own
  `operatorBlocked` array says authenticated states need a review tenant that
  does not exist.
- **Motion is never rendered.** The contract forces `reducedMotion: "reduce"`
  and `animationPolicy: "disabled"`. So the reduced-motion path is thoroughly
  evidenced and the animated path is evidenced nowhere, while the film shows
  motion. Recorded in `evidence/E05-E06-audit.md` and unchanged by this work.
- **This run predates one change in this package** — the delete revalidation
  fix in §3, which landed after it. That change is a server action no
  Playwright case exercises (no test deletes a workspace), and it is covered by
  its own registered contract test with a fail-before. Stated so the sequence
  is reconstructible rather than implied.

## 5. Social preview — **one defect, reported, not fixed**

### `/s/[token]` — correct on every count

- `src/app/s/[token]/page.tsx:29` sets
  `robots: { index: false, follow: false, noarchive: true, nosnippet: true }`.
- `src/app/s/layout.tsx` sets the same on the layout, so an unavailable link
  that exits through `notFound()` before dynamic metadata resolves still
  carries it.
- `next.config.ts` sends `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet`
  as a header on `/s/:path*`.
- `src/app/robots.ts` disallows `/s`.
- The unfurl carries the timeline's label and the sentence
  `A shared couple timeline.` and nothing else. `alternates.canonical` and
  `manifest` are nulled so the operating product's identity cannot leak into
  the artifact.

Four independent controls for one property. Per the orchestrator's ruling this
was verified and left alone.

### `/p/[slug]` — the defect

`src/app/p/[slug]/page.tsx:21-58` builds the OpenGraph title and description
from the workspace name and its domain label. For a wedding workspace called
"Mara and Finn", what unfurls in WhatsApp when the couple sends the link to
their mother is:

> **Mara and Finn, Wedding planner workspace**
> Mara and Finn, a real wedding planner workspace made public on Tasks. Same
> items, four lenses: board, list, timeline, calendar.

Four things wrong with that, in order of seriousness:

1. **It is product marketing on a couple's wedding page.** D-011 point 2: *"If
   it reads as marketing on someone's wedding page, the thing being sold is
   gone."* "Same items, four lenses" is feature copy.
2. **"made public on Tasks" will be false by default.** D-033 makes wedding
   workspaces `noindex` by default with search visibility an explicit opt-in.
   The unfurl would tell every recipient the opposite.
3. **"Wedding planner workspace"** describes the couple as a planner and names
   an internal product domain. It is a tier name leaking onto a keepsake.
4. The description leads with the couple's names twice.

**Not fixed, deliberately.** `/p/[slug]` is being changed concurrently under
R-031 by the E06.01-E06.07 group, and `generateMetadata` is exactly the
function their `noindex` work lands in. Editing it here would collide. The fix
is one function and belongs in that change.

**Suggested replacement, for whoever lands R-031** — title `Mara and Finn`,
description `A shared wedding timeline.` Nothing else. It matches what `/s`
already does, and it is the only version that survives being read by a
grandparent.

## 7. Cross-browser — **NOT TESTED**

`experience/playwright.config.ts` sets `browserName: "chromium"` for every
project and `channel: "chrome"` outside CI. There is one engine. The four
projects are four viewport sizes, not four browsers.

So nothing here says anything about Safari, which is the browser most of a
wedding's guests will actually use. Given that the artifact leans on container
queries, `inset-block`/`inset-inline` logical properties and `color-mix`, that
is a real hole rather than a formality. **Stated as untested.**

## 2. E08.08 — criterion to proof

### C1 · The two logs are defined where they are enforced

`app/src/server/operational-log.ts`. An audit log answers who did what to
whose data, when: written deliberately, retained, tamper-evident, evidence.
An operational log answers why a request failed: written incidentally,
retained by the platform, governed by nobody. Both audit tables are named
(`workspace_events`, `entitlement_events`), and a test fails if that
definition is removed.

### C2 · No server-scope log line carries content or a credential

`app/src/server/operational-log-contract.test.mjs`, RULE 2. Proven to fire on
seven shapes: `document-uri`, `args.to`, `args.html`, `task.title`, a guest
list, `row.dietary`, `distinctId`. Proven **not** to fire on four ordinary
error logs, so it is a rule and not a blanket ban.

Two sites legitimately need the payload and are gated on
`NODE_ENV === "development"`. Each carries a greppable `// op-log-safe:`
waiver, and a test proves a waiver only exempts a site when it is written
down.

### C3 · A new logging site cannot appear unreviewed

RULE 1: a ratchet over 51 recorded server-scope logging sites across 31 files.
An unrecorded file fails; a file whose count grew fails; a stale entry for a
file that no longer logs fails, so the ratchet cannot be spent on a deleted
file. A separate test asserts the comparison direction, which is the one thing
a ratchet can get silently backwards. A guard test asserts the scan finds more
than 20 sites, so a moved source tree fails rather than passing vacuously.

### C4 · Two real leaks closed at source

**The CSP collector.** `app/src/app/api/csp-report/route.ts` logged the
browser-supplied `document-uri` verbatim. On a shared workspace that URL is
`/share/<token>` or `/s/<token>` — a **bearer credential** — written into the
platform's function log. `sentry-scrub.ts` already redacted exactly that shape,
so the same string was safe when thrown and unsafe when logged. Now routed
through `opLog`.

**The email sender.** `app/src/server/email.ts` logged the recipient address,
the subject line and the first 120 characters of the body whenever
`RESEND_API_KEY` was unset. That is a **configuration state, not an
environment**: a production deploy that lost the key would have written every
couple's address and a slice of every wedding email into the operational log.
The full payload is now gated on `NODE_ENV === "development"`; every other
environment gets a line naming the recipient's domain only.

### C5 · Append-only enforcement is real, or reported as absent

`studio/scripts/apply-audit-ledger-triggers.test.mjs`, 9/9 pass, including a
case titled *"DEFECT: a database built from the baseline lets an audit line be
edited and deleted"* — which passes today, because that is the true state of a
fresh database. `grep -c "CREATE TRIGGER" drizzle-entitlements/0000_init.sql`
returns **0**: drizzle cannot express a trigger, so the regenerated baseline
creates the audit ledger as an ordinary table.

### C6 · Absence is a failing run

`pnpm audit:triggers:verify` exits non-zero when either trigger is missing.
`check-entitlements-integrity.mjs`'s `summarise` returns `ok: false` when
enforcement is applicable and incomplete, held by a test that asserts the run
fails before installation and passes after.

### C7 · No comment claims an enforcement the schema does not deliver

`studio/src/lib/entitlements-db/audit.ts` used to state that append-only "is
enforced by SQLite triggers from `migrate-access.mjs`". True of one hand-run
database, false of every database built since the 2026-07-31 reset. Corrected
to say plainly that the hash chain **detects** and the triggers **prevent**,
and held by a test that fails if the retired wording returns.

### C8 · Monitoring and alerting, stated as fact

This is the part with no code in it, and it is the most important line in this
document.

- **Sentry is integrated and not provisioned.** `app/src/instrumentation.ts:17`
  returns early when `SENTRY_DSN` is unset. `studio/docs/INFRASTRUCTURE.md`
  records Sentry, PostHog, Upstash and production Anthropic as "integrated in
  app code, none provisioned". **An unhandled error in production is currently
  observed by nobody.**
- **There is no alerting of any kind.** No pager, no threshold, no
  notification, no escalation path. No such mechanism exists in either
  repository.
- **Studio has no error reporting at all**, not even an unprovisioned
  integration.
- **The app's audit log covers two event kinds**, `inviteSent` and
  `inviteAccepted`, written from `src/server/actions/settings.ts`. Removing a
  member, changing a role, creating or revoking a share link, publishing a
  workspace and deleting an account are **unaudited**.
- **The entitlements audit ledger is genuinely strong**: hash-chained, written
  inside the same transaction as the state change, called from 15 sites across
  `writes.ts`, `codes.ts`, `founding-numbers.ts`, `gdpr.ts` and
  `venue-billing.ts`. It is the best-built control in either repository, and
  the only thing it was missing was physical enforcement, which is now
  installable and checkable.

Nothing in this task produced a surface that states or implies monitoring
exists where it does not (D-016).

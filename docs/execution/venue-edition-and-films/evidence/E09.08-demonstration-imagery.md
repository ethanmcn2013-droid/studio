## 2. The audit

### 2.1 Method, so it can be re-run

Five passes, all mechanical, all over the live trees (backups and `_wt-*`
worktrees excluded as stale duplicates).

1. **Enumerate.** Every raster file under `app/public` and `studio/public`,
   by extension: `png jpg jpeg webp avif gif tif tiff bmp heic`.
2. **Read what the file itself says.** Parse each file's own headers for
   dimensions, then scan for EXIF `Make`, `Model`, `Software`,
   `DateTimeOriginal`, `Artist`, `Copyright`; for XMP; for a C2PA/JUMBF
   marker; for the IPTC `digitalSourceType` field; and for PNG `tEXt`/`iTXt`
   chunks. A camera `Make`/`Model` is positive evidence of a real photograph.
3. **Map every reference.** For each raster, search every source file in
   `app/src`, `studio/src`, `studio/emails`, `studio/public/brand`,
   `studio/public/hq`, `collateral/src`, `collateral/dist` for its basename,
   and classify the referring surface.
4. **Test against the real venue universe.** Load all 219 real venue names from
   `private/venues.csv` and test each against every asset path and against
   every `alt`, `caption` and `aria-label` string in the app and studio source
   trees. Names are never printed; only counts and hit locations.
5. **Copy sweep.** Test the same alt/caption/aria strings against the E09.10
   never-list, and against the em dash and exclamation-mark prohibitions.

## 3. The register

### 3.1 Where it lives

| Artifact | Path | Purpose |
|---|---|---|
| The data | `studio/src/lib/demonstration-imagery/register.json` | Surfaces, shots, assets, acknowledged real rasters |
| The schema and the runtime rule | `studio/src/lib/demonstration-imagery/registry.ts` | Types, the R-011 surface policy, `refusalFor(asset, surface)` |
| The check | `studio/scripts/check-demonstration-imagery.ts` | Fails the build on a violation |

It is deliberately **not** under `public/`. A register carries every prompt and
every rights position; serving it publicly would publish the working method of
the demonstration and, worse, would repeat the mistake already sitting at
`studio/public/brand/collateral/venue/wedding-seed.md`, which is a publicly
served file containing a synthetic guest health record.

**Where the images themselves go**, declared once so the coverage sweep can be
exhaustive:

| Repo | Directory |
|---|---|
| `app` | `public/demonstration/` |
| `studio` | `public/brand/assets/demonstration/` |
| `signal-motion` | `public/demonstration/` |

An asset registered outside its repo's declared directory is a `layout` failure.
This is the mechanism that makes "every demonstration image is registered"
checkable rather than aspirational: the sweep walks one directory per repo and
every raster in it must have an entry.

### 3.2 The asset schema

Every field is required, because every field is the answer to a question
somebody asks after the fact, and a register with optional provenance is not a
register.

```ts
{
  id, shotId,
  repo,                       // app | studio | signal-motion
  path,                       // repo-relative, forward slashes
  sha256,                     // 64 lowercase hex, re-hashed by the check
  mediaType,                  // image/webp | image/jpeg | image/png | image/avif
  dimensions: { width, height },
  bytes,
  generator: { model, version, tool, seed },
  prompt, negativePrompt,
  generatedOn,                // YYYY-MM-DD
  rightsPosition,
  permittedSurfaces: [ surfaceId, … ],
  containsFaces,              // boolean
  founderAcceptanceNote?,     // required when containsFaces on a note-required surface
  altText, caption,
  reviewedBy, reviewedOn, reviewVerdict,   // accepted | rejected | pending
  acceptanceTestsPassed: [ "AT-1", … ]
}
```

`generator.seed` is `"none"` where the tool exposes none, and never omitted. The
seed is the difference between a prompt that describes an image and a record
that could reproduce it.

### 3.3 What the check script proves

`tsx scripts/check-demonstration-imagery.ts`

1. **Strict schema.** Unknown keys are failures, not warnings. A typo'd
   `containsFaces` field would silently disable the R-011 rule, so a typo is a
   build break.
2. **The file is the file.** Every registered path exists, in its declared repo,
   with the declared byte length and the declared sha256, re-hashed from disk. A
   mismatch means the file on disk is not the file that was reviewed.
3. **Dimensions and resolution.** Read from the file's own header and compared
   to the register, and against the shot's declared `minLongEdgePx`.
4. **R-011, as an assertion.** No asset with `containsFaces: true` may be
   permitted on a surface whose `facesPolicy` is `forbidden`. The rule is
   applied at shot level too, before anything is generated, so a face is
   refused at planning time rather than at review time.
5. **Creative gate criterion 11.** A generated face on a
   `founder-note-required` surface must carry a non-empty
   `founderAcceptanceNote`.
6. **Nothing unaccepted is live.** An asset whose verdict is `pending` or
   `rejected` may not be referenced from any source file in any of the three
   repos.
7. **Coverage.** Every raster sitting in a demonstration directory has a
   register entry. This is the gate criterion, mechanically.
8. **E09.10 on alt text and captions.** Never-list terms, em dashes and
   exclamation marks fail. Where a surface declares
   `captionRule: visible-caption-required`, the caption must carry the P14
   substitute *"Example venue and couple."*
9. **A-007.** Acknowledged real material still hashes to the audited value, and
   is referenced from nothing outside its declared permitted surfaces.

**Verified.** On the current tree the check reports 10 surfaces, 19 shots,
0 assets, 2 acknowledged real raster sets and **0 failures**. A deliberately
malformed entry — unknown key, empty reviewer, empty model, empty prompt, empty
rights position, missing file, a face on both a `forbidden` and an
`imageryPermitted: false` surface, and never-list terms plus an em dash and an
exclamation mark in the alt text and caption — produced **14 distinct failures**
and exit code 1. The negative test is the proof; a check that has only ever
passed has not been tested.

### 3.4 Adding an image, in four steps

1. Write the shot into `shots` **before generating anything**. The shot carries
   the reason it exists, so a shot nobody can justify is cut before it costs
   anything.
2. Generate. Record model, version, tool, seed, prompt, negative prompt and
   date at the moment of generation, not afterwards from memory.
3. Apply section 5's acceptance test. Record the verdict and the reviewer's
   name. A rejected image stays in the register with `reviewVerdict: rejected`;
   the reject record is evidence that the bar was applied.
4. Add the `assets` entry with the real sha256 of the real file, and run the
   check. It must pass before the file may be referenced from any source file.

## 5. The acceptance test

The test a human applies to a generated image before it may be used. **"Looks
real" is not a test** — it is a feeling, it is not repeatable, and two reviewers
will not agree on it. Each test below is a binary question with a stated method.
A single failure is a reject. R-011's own rule applies: **cut the shot rather
than ship it.**

Every test is applied at 100% zoom on a colour-managed display, and again at the
size the image will actually appear. Both passes must pass.

**AT-1 — Extremities.** Count the fingers on every visible hand. Five, each
separately articulated, each with a nail plate that meets the fingertip. Trace
every limb to a plausible origin. Any count other than five, any fusion, any
limb that begins nowhere: reject.

**AT-2 — Text.** Scan the entire frame for lettering: signage, menus, place
cards, book spines, labels, packaging, number plates, embroidery, engraving. The
frame must contain **zero** characters unless they were composited afterwards
from repository text. Garbled or plausible-but-wrong lettering: reject.

**AT-3 — Repetition.** Identify every repeated element — chair backs, window
panes, balusters, table settings, glassware, stems. Follow the series. Any break
in the pattern, any member that terminates in nothing, any change of pitch
mid-run: reject.

**AT-4 — Occluded continuity.** List every line that passes behind an object:
table edges, cornices, chair rails, skirting, paths, horizon. Confirm each
re-emerges at the same angle and the same height. A line that steps: reject.

**AT-5 — Light.** Name the light source and its direction out loud. Then check
every shadow against it, and every specular highlight on glass, cutlery, water
and polished wood. Two shadows disagreeing about where the sun is: reject.

**AT-6 — Depth.** Confirm the blur gradient is monotonic with distance. Any
background element sharper than a nearer one, or a blur boundary that does not
follow an object edge: reject.

**AT-7 — Materials.** Fabric drapes with weight and creases that follow the
drape. Water has a meniscus and a refraction offset. Flames have a hot core.
Every stem reaches a container. Every leg reaches the floor: reject if not.

**AT-8 — Scale.** Measure one known object in pixels — a dinner plate is about
27 cm, a wine glass about 20 cm, a dining chair seat about 45 cm from the floor,
a door about 2.0 m. Derive the scale, then check three other objects against it.
Any object more than 20% off: reject.

**AT-9 — Place.** Show the image to a reviewer with no context and ask, "where
is this?" If the first answer is not Ireland, or Britain and Ireland, the shot
fails. Explicit tells that are automatic rejects: olive, cypress or palm trees,
Mediterranean roof tiles, US or continental electrical fittings, non-Irish
number-plate format, window proportions or glazing bars that read American
colonial, and any grading that reads as California golden hour.

**AT-10 — Venue resemblance.** The reviewer holds the 219-row private venue
universe. If anyone who knows the Greater Limerick market names a real venue on
sight, the shot is **cut, not adjusted**. A near-miss is worse than a miss,
because the film goes to those venues by name.

**AT-11 — Faces.** Zero identifiable human faces at any size at which the eyes
resolve. On both films, the public Timeline demonstration, the milestone
photographs and the outreach email this is absolute and no founder note can
waive it. Elsewhere a face requires a written founder acceptance recorded in the
register.

**AT-12 — Register.** The image passes `BRAND.md` §3 restraint: no stock
gesture, nobody laughing at food, no arms in the air, no vignette, no HDR halo,
no clarity slider, no teal-and-orange grade. If it looks like a stock
photograph, it fails for that reason alone.

**AT-13 — Declaration.** Wherever the image is placed, the P14 declaration is
present in the form that surface's `captionRule` requires: a visible caption
carrying *"Example venue and couple."*, an alt-text declaration, or the film's
end-card declaration.

**AT-14 — Provenance.** The register entry exists, records model, version, tool,
seed, prompt, negative prompt, date, rights position, reviewer and verdict, and
`tsx scripts/check-demonstration-imagery.ts` passes. Until it does, the image
may not be referenced from any source file.

**AT-15 — Amateur register** (milestone photographs only, MS-01 to MS-03). The
opposite bar. Ask a reviewer, "who took this?" If the answer is "a
photographer", the shot fails. Required tells: an off-level horizon, an
uncomposed crop, an incidental object at the frame edge, and no shallow
depth-of-field bokeh.

## 6. The QA gate

R-011's mitigation says generated imagery is a first-class QA item at **E05.12,
E09.08 and E14.18**, not a background asset. This is that gate, written so it
can be run rather than agreed with. Each line is checkable and names its
evidence.

### 6.1 Gate A — at E09.08, before any image is used anywhere

- [ ] `tsx studio/scripts/check-demonstration-imagery.ts` exits 0.
      *Evidence: the command output.*
- [ ] Every shot in the register that reached `status: generated` has an
      `assets` entry, and every entry's `acceptanceTestsPassed` lists every
      test in that shot's `acceptanceTests`.
      *Evidence: the check output.*
- [ ] Every rejected image is still in the register with
      `reviewVerdict: rejected` and a reviewer name. **A gate with no rejects
      in its record has not been applied.**
      *Evidence: the register.*
- [ ] The reviewer is named, is a person, and is not the agent that generated
      the image.
      *Evidence: `reviewedBy`.*
- [ ] Zero assets carry `containsFaces: true` on a `forbidden` surface, and
      every face anywhere carries a founder acceptance note.
      *Evidence: the check output, R-011 and creative gate criterion 11.*
- [ ] No asset path lies outside its repo's declared demonstration directory.
      *Evidence: the check's `layout` rule.*

### 6.2 Gate B — at E05.12, design-system review and visual baselines

- [ ] Every captured product surface that shows an image shows a **registered**

### 6.4 The standing refusal

If a shot fails any test and cannot be regenerated to pass within the time
available, **the shot is cut**. It is not softened, not blurred, not
colour-graded around, and not shipped small enough to hide. That is R-011's own
mitigation and it is the only one of the four that costs anything, which is why
it is written down here where a tired reviewer will find it.

## 7. Acceptance criteria this document supplies for E09.08

1. An image-provenance register exists, is committed, and records model,
   version, tool, seed, prompt, negative prompt, date, rights position,
   permitted surfaces, face flag, reviewer and verdict for every demonstration
   image.
2. A check script validates the register against the repository and **fails**
   on: schema violation, missing file, hash mismatch, dimension mismatch,
   resolution below the shot minimum, a face on a forbidden surface, a face
   without a founder note, an unaccepted asset referenced from source, an
   unregistered raster in a demonstration directory, or a never-list term, em
   dash or exclamation mark in alt text or a caption.
3. The check script has been proven to fail, not only to pass: a deliberately
   malformed entry produces a non-zero exit and names each violation.
4. Every demonstration surface that needs imagery has a shot with a stated
   reason, a generation prompt and a negative prompt.
5. R-011's face rule is expressed as data, not prose: every surface carries a
   `facesPolicy`, and the shot list contains zero faces.
6. A named human reviewer has applied the fifteen acceptance tests to every
   generated image, and the rejects are recorded alongside the accepts.
7. An exhaustive audit of both repositories confirms no unapproved real venue or
   couple material appears on any demonstration surface, by enumeration of every
   raster asset and by testing every asset path and every alt, caption and aria
   string against all 219 real venue names.
8. Real material that does exist is registered with its rights position and its
   permitted surfaces, so the confirmation is a control rather than a snapshot.

**Criteria 1 to 5, 7 and 8 are met by this document and the three committed
files. Criterion 6 cannot be met until images exist, and no image exists.**

  register so film stills can be registered, but `signal-motion/**` belongs to

  `assets[]` to carry image hashes is that lane's work, requested rather than

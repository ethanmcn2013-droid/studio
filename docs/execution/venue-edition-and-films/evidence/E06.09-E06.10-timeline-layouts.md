# E06.09 and E06.10 — two Timelines, already shipped, and the evidence that was missing

Evidence for E06.09 and E06.10. Written 2026-08-03 in worktree `_wt-wp14` (app,
branch `claude/wp14-timeline`). Acceptance criteria were written before the
audit. One document covers both tasks because they are two halves of one
component and share one contract file.

---

## The headline in one paragraph

Both layouts ship and both are correct. The vertical mobile Timeline is not the
desktop rail rewrapped: it flips the coordinate system, replaces
collision-avoidance with showing every label, and rotates the Today marker. The
desktop editorial Timeline has three container tiers. **What did not exist was
any evidence.** The one file that asserted the artifact's design contract,
`timeline-artifact-contract.test.mjs`, had never been registered in
`package.json` — so it had never run in CI — and when run by hand it was **red**,
with two assertions stale against a component that had since been improved.
That file is now green, extended, and registered. Two further defects were
found that are not this package's to fix and are referred with their lines.

---

`evidence/E05-E06-audit.md` records both layouts as shipped in commit

| Claim in the audit | Verified in this worktree |
|---|---|
| Vertical mobile Timeline at `timeline-artifact.module.css:967-1145` | **Correct.** `@container timeline-artifact (max-width: 620px)` opens at line 967 and closes at 1145. |
| Rail becomes `width: 2px; height: auto` | **Correct**, line 1053-1058, on `.progressGeometry`. |
| Milestones position by `inset-block-start` | **Correct**, line 1104-1107. |
| Today marker rotates | **Correct**, lines 1079-1085: `width: 2rem; height: 1px` against the base rule's `width: 1px; height: 2rem` at 427-433. |
| Collision-avoidance replaced by showing every label | **Correct**, lines 1121-1125. |
| Desktop editorial third tier at `min-width: 980px` | **Correct**, line 622. |
| "Different objects across the breakpoint, not one object rewrapped" | **Correct**, and now asserted. |

**One correction to the audit's line reference.** The audit gives the desktop
editorial layout as ":375-400 plus a third tier at min-width 980px". Lines
375-400 are `.stageViewport`, `.stage` and `.progressGeometry` — the horizontal
rail's own geometry, which is right — but the mid tier is at line 953
(`max-width: 980px`) and the widest tier at 622 (`min-width: 980px`). Three
tiers, not two. Immaterial to the conclusion.

**One thing the audit did not record and it is the finding.** The layouts are
driven by **container** queries, not viewport media queries
(`container-name: timeline-artifact; container-type: inline-size`, lines
12-13). That is why the same artifact is correct inside the owner's panel and
inside the phone preview as well as on a full page, and it is a materially
better piece of engineering than a viewport breakpoint. It is now asserted, and
the assertion also refuses any future viewport media query that decides layout.

## 1. The finding: an unregistered, red design contract

```
$ grep -c "timeline-artifact-contract" package.json
0

$ node --test src/modules/timeline/components/artifact/timeline-artifact-contract.test.mjs
✖ the artifact keeps the locked Option D identity and line-first hierarchy
✔ the phone preview renders the exact artifact in compact mode and cannot track views
✔ the milestone rail exposes roving keyboard navigation and touch-safe targets
✔ motion has a reduced-motion path and the metric swaps as a single face
✔ motion preference is hydration-safe and never changes the initial metric subtree
✔ the owner studio owns vertical scrolling inside the app shell
✖ owner surfaces embed the exact artifact without claiming a document-height viewport
✔ low-information timelines receive density-only refinements after the generic mobile rules
✔ undated milestone copy states the truth without implying a future date
ℹ tests 9  ℹ pass 7  ℹ fail 2
```

**Both failures were in the test, not the component, and both are instructive.**

**Failure 1** — `assert.doesNotMatch(artifact, /StudioRail|StudioBar|dashboard/i)`.
The rule is "no studio chrome inside the artifact". It fired on
`timeline-artifact.tsx:70`, a JSDoc line that reads *"the StudioBar already
provides identity, so the owner view suppresses it rather than stacking two
wordmarks"* — the rule being honoured, described. The assertion now runs against
a comment-stripped copy, because comments are documentation and not rendered
output.

**Failure 2** — `assert.match(ownerProject, /<TimelineArtifact timeline=\{timeline\} embedded \/>/)`.
The owner project page now reads
`<TimelineArtifact timeline={timeline} embedded showProductHeader={false} />`
(`src/modules/timeline/app/plan/[projectSlug]/page.tsx:295`). That is a
deliberate improvement — it stops the artifact's wordmark stacking under the app
shell's identity — and a literal-string assertion made it look like a
regression. The assertion now matches on the `embedded` prop regardless of prop
order, and a new line asserts `showProductHeader={false}` so the improvement is
protected rather than merely tolerated.

**Neither the component nor the CSS was changed.** Every edit in this package is
to the test file.

**Why this matters more than the two assertions.** A design contract in an
unregistered file is the same defect class as R-028 (D-011's rate floor
enforced in a test and nowhere else) and the same class as the three privacy
tests found unregistered in `evidence/E05-production-blocker-app-gate.md`. It
is worse here in one respect: because it never ran, it went red and stayed red,
and nobody could have known.

## 2. Criterion by criterion

### E06.09 C1 — the rail flips its coordinate system — **MET**

```
✔ the rail flips its axis below 620px rather than being the same rail, rewrapped
```

Asserted as a pair, base rule against the vertical block:

| Property | Base (editorial) | Below 620px (vertical) |
|---|---|---|
| `.progressGeometry` | `inset-inline: 0; height: 2px` | `width: 2px; height: auto` |
| `.todayMarker` | `width: 1px; height: 2rem` | `width: 2rem; height: 1px` |
| `.milestone` | positioned by inline offset | `inset-block-start: var(--timeline-position)` |
| completed rail | `.completedRail` | `.completedRail { display: none }`, `.completedRailVertical { display: block }` |

The vertical block is extracted by index rather than by copying rules into the
test, so the assertions read the shipped CSS rather than a snapshot of it.

### E06.09 C2 — the Today marker rotates with it — **MET**

Same test. The marker becomes a horizontal dash and its label moves to
`inset-inline-start: calc(50% + var(--space-4))` with a `--paper` background so
it clears the rail (lines 1092-1098).

### E06.09 C3 — every label shows on the vertical rail — **MET**

```
✔ collision avoidance is replaced by showing every label on the vertical Timeline
```

Base rule (line 614-618): `.milestone[data-labelled="false"] .milestoneLabel`
gets `opacity: 0; pointer-events: none`. Vertical block (1121-1125): the same
selector gets `opacity: 1; pointer-events: auto`. A vertical rail has room for
all of them, so nothing is hidden.

### E06.09 C4 / E06.10 C1 — container width, not viewport width — **MET**

```
✔ both Timelines are sized by container width, so the artifact is correct inside the phone preview too
✔ the desktop editorial Timeline keeps its own widest tier
```

`container-name: timeline-artifact`, `container-type: inline-size`, three tiers
at `min-width: 980px`, `max-width: 980px` and `max-width: 620px`, plus a fourth
refinement at `max-width: 390px`. The new assertion also collects every
`@media (… width …)` in the stylesheet and asserts the list is **empty**, so no
future viewport breakpoint can quietly take over layout.

The only `@media` rules in the file are `prefers-reduced-motion: reduce` and
`print`, which are correct.

### E06.09 C5 — the keyboard contract is unchanged — **MET**

Existing assertions, now running in CI for the first time:

```
✔ the milestone rail exposes roving keyboard navigation and touch-safe targets
```

Left, Right, Home, End, roving `tabIndex={index === boundedFocusIndex ? 0 : -1}`,
`--x-timeline-hit: 3rem` touch targets. In the component,
`timeline-artifact.tsx:568-569` carries `aria-expanded` and `aria-controls` on
the selected point and `:604-607` is the polite live region announcing open and
closed. Escape closes the detail (`:447-450`).

### E06.09 C6 / E06.10 C4 — reduced motion, and hydration safety — **MET**

```
✔ motion has a reduced-motion path and the metric swaps as a single face
✔ motion preference is hydration-safe and never changes the initial metric subtree
```

The second is the more interesting one and it was already there: the motion
preference is read exactly once, through a hydration-gated wrapper, so server
and first client render choose the same subtree. The assertion counts the
occurrences of `useReducedMotion()` and fails at two.

### E06.10 C2 — the horizontal rail's affordances belong to the wide layout — **MET**

`.stageViewport { overflow-x: auto }` with hidden scrollbars in the base rule;
`overflow-x: hidden` inside the vertical block. Asserted in the new
desktop-tier test.

### E06.10 C3 — owner surfaces embed the same artifact — **MET**

```
✔ owner surfaces embed the exact artifact without claiming a document-height viewport
```

Both owner surfaces pass `embedded`; the owner project page additionally
suppresses the artifact's own wordmark. `.artifact[data-embedded="true"]` sets
`min-height: auto` so an embedded artifact does not claim a document-height
viewport inside a panel.

### E06.09 C7 / E06.10 C5 — accessibility and overflow at four widths — **MET**

Real run, not asserted from reading. See §4.

### E06.09 C8 / E06.10 C6 — it runs in CI — **MET**

Registered in `package.json`'s `test` script, in the `node --test … .mjs`
segment alongside the other contract tests. Confirmed by its assertions
appearing in the full-suite output:

```
✔ the rail flips its axis below 620px rather than being the same rail, rewrapped (1.179ms)
✔ the desktop editorial Timeline keeps its own widest tier (1.167ms)
```

### E06.10 C7 — contradictions found, reported — **MET**

Two, both referred rather than fixed. See §3.

## 3. Two defects found, neither fixed, and why

### 3.1 The wordmark above the couple's names

`src/modules/timeline/components/artifact/timeline-artifact.tsx:279-281`:

```tsx
<span className={styles.productMark} aria-label="timeline" data-timeline-wordmark>
  timeline<span aria-hidden="true" />
</span>
```

`ProductIdentity` renders at the top of the shared page, above `<h1>{timeline.label}</h1>`
— the couple's names. D-011 point 2 is explicit: *"One line in the footer. No
logo, no badge, no 'powered by' in the viewport."* The footer line already
exists and is correct (`:678-681`, "A Signal Studio product").

`experience/tests/critical-experiences.spec.ts` asserts the wordmark's exact
text, so **a passing test currently locks in what the ratified decision
forbids**. `evidence/E05-E06-audit.md` found the same thing.

Not fixed here for three reasons: it is E06.08's output and E06.08 is already
approved, so changing it is a change request rather than a tidy-up; it is a
visible design change to the film's hero surface; and it requires editing an
e2e assertion, which turns a design question into a green-gate question. **This
is a founder call.**

### 3.2 `detailNote`'s generated sentences

`timeline-artifact.tsx:320-324` returns one of three fixed sentences:

- "This milestone is part of the story so far."
- "This is the next point on the shared journey."
- "This milestone comes later on the shared journey."

These are front-facing copy on a couple's wedding page. "Journey" as a noun is
on the banned list. The first sentence is good; the second and third are filler
that says nothing the status label above them has not already said. Referred
rather than rewritten because E06.04 owns the detail panel.
